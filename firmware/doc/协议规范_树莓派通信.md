# RL-CAT 树莓派 ↔ STM32 通信协议规范

> **文档编号**：FW-PROTO-001
> **版本**：v1.0
> **日期**：2026-10-09
> **面向对象**：STM32 固件开发者 + 树莓派端开发者

## 0. 设计目标

| # | 目标 | 理由 |
|---|---|---|
| 1 | **确定性延迟** | RL 控制环 100 Hz（10 ms），抖动必须小 |
| 2 | **能检测丢帧** | 有序列号 + CRC |
| 3 | **安全降级** | 链路断了 STM32 要自己识别并趴下 |
| 4 | **双向对称** | 下行指令 + 上行完整观测 |
| 5 | **解析快** | 固定偏移的二进制，不用字符串解析 |
| 6 | **可扩展** | 有版本号 + 类型字段，方便加消息 |

## 1. 物理层

| 项 | 值 |
|---|---|
| **接口** | USART1（STM32 侧）↔ `/dev/ttyAMA0` 或 USB 串口（Pi 侧） |
| **波特率** | **1 000 000** (1 Mbps) |
| **数据格式** | 8 数据位 / 无校验 / 1 停止位（**8N1**） |
| **流控** | 无（`UART_HWCONTROL_NONE`） |
| **电平** | 3.3 V TTL |
| **STM32 引脚** | PA9 = TX，PA10 = RX |
| **接线** | **标准交叉**：STM32 TX → Pi RX、STM32 RX ← Pi TX，GND 共地 |

**⚠️ 两条链路的接线方式不同，别搞混：**

| 链路 | 接线 | 依据 |
|---|---|---|
| **USART1 ↔ 树莓派** | **交叉**（TX→RX、RX→TX） | 常规串口接法 |
| **USART2 ↔ 舵机控制板** | **直连**（TX→TX、RX→RX） | ⚠️ 控制板端子丝印按 MCU 侧标注，见《固件设计书》§2.3 |

**⚠️ 3.3 V 电平匹配：树莓派 GPIO 是 3.3 V，直连即可。不要接 5 V。**

### 1.1 带宽预算

```
TEL_FAST  : 103 字节 × 100 Hz = 10 300 B/s
CMD_JOINT :  38 字节 × 100 Hz =  3 800 B/s
TEL_STATUS:  47 字节 ×  10 Hz =    470 B/s
──────────────────────────────────────────
合计                           ≈ 14 600 B/s

1 Mbps 的实际有效载荷率 ≈ 100 000 B/s（8N1，每字节 10 位）
占用率 ≈ 15%
```

**✅ 带宽很宽裕，不需要压缩。**

### 1.2 延迟预算

```
STM32 采集 + 组帧             0.5 ms
物理传输（103 B @ 1 Mbps）    1.03 ms
Pi 推理（ONNX, MLP 256-128-64） ~1.0 ms
物理传输（38 B @ 1 Mbps）     0.38 ms
STM32 解析 + 限幅             0.1 ms
──────────────────────────────────
端到端                        ≈ 3.0 ms
```

**✅ 约 3 ms，占 10 ms 周期的 30%。**

**⚠️ 但这是"阻塞等待模型 A"的延迟。如果用 §7.3 的模型 B（不等指令，用上一帧），端到端延迟约 13 ms。**

## 2. 帧格式（统一）

**所有消息共用同一个帧头结构：**

```
┌──────┬──────┬──────┬──────┬──────┬─────────────┬───────┐
│ HEAD0│ HEAD1│ LEN  │ SEQ  │ TYPE │  PAYLOAD    │ CRC16 │
│ 0xAA │ 0x55 │  1B  │  1B  │  1B  │   LEN 字节   │  2B   │
└──────┴──────┴──────┴──────┴──────┴─────────────┴───────┘
  偏移0   偏移1   偏移2   偏移3   偏移4    偏移5      偏移5+LEN
```

| 字段 | 偏移 | 长度 | 说明 |
|---|---|---|---|
| `HEAD0` | 0 | 1 | 固定 `0xAA` |
| `HEAD1` | 1 | 1 | 固定 `0x55` |
| `LEN` | 2 | 1 | **PAYLOAD 长度**（不含头、不含 CRC），最大 128 |
| `SEQ` | 3 | 1 | 序列号 0–255 循环，**用于检测丢帧** |
| `TYPE` | 4 | 1 | 消息类型（见 §3） |
| `PAYLOAD` | 5 | LEN | 负载 |
| `CRC16` | 5+LEN | 2 | **小端序**，覆盖 `LEN` 到 `PAYLOAD` 末尾 |

**帧总长 = 7 + LEN 字节**

**⚠️ 为什么用双字节头 `0xAA 0x55`：** 单字节头在二进制流里容易误触发。双字节的误触发概率极低，且配合 LEN + CRC 几乎不可能误判。

**⚠️ CRC 的计算范围：从 `LEN`（偏移 2）到 `PAYLOAD` 末尾（偏移 5+LEN-1），共 `LEN + 3` 字节。** 不包含两个头字节。

## 3. 消息类型

| TYPE | 方向 | 名称 | 频率 | PAYLOAD 长度 | 帧总长 |
|---|---|---|---|---|---|
| `0x01` | Pi → STM32 | **CMD_JOINT** | 100 Hz | 31 | 38 |
| `0x02` | STM32 → Pi | **TEL_FAST** | 100 Hz | 96 | 103 |
| `0x03` | Pi → STM32 | CMD_MODE | 事件 | 2 | 9 |
| `0x04` | STM32 → Pi | TEL_STATUS | 10 Hz | 40 | 47 |
| `0x05` | Pi → STM32 | CMD_CALIB | 事件 | 1 | 8 |
| `0x06` | STM32 → Pi | TEL_LOG | 事件 | 2–62 | 9–69 |
| `0x07` | STM32 → Pi | TEL_ACK | 事件 | 2 | 9 |
| `0x7F` | 双向 | HEARTBEAT | 1 Hz | 0 | 7 |

**⚠️ 未识别的 TYPE 必须被静默丢弃（不要复位、不要报错刷屏），但要在状态里计数。**

## 4. 各消息的精确格式

### 4.1 `CMD_JOINT` (0x01) — Pi → STM32

**下行关节目标角。**

```
偏移  类型      字段          单位        说明
──────────────────────────────────────────────────────────────
0     uint8     mode          枚举        运行模式，见 §4.2
1     uint8     flags         位域        见 §4.3
2     int16[12] q_target      0.0001 rad  12 个关节目标角，小端
26    uint8     reserved      —           保留（填 0）
27    int16     kp_scale      0.01        预留：PD 增益缩放
29    uint8     led           位域        LED 控制（bit0 = 状态灯）
30    uint8     reserved2     —           保留（填 0，用于 4 字节对齐）
──────────────────────────────────────────────────────────────
LEN = 31   →  帧总长 = 38 字节
```

**⚠️ `q_target` 的编码：**

```c
// 编码（Pi 侧）
int16_t enc = (int16_t)(q_rad / 0.0001f);     // 例：0.5236 rad → 5236

// 解码（STM32 侧）
float q_rad = (float)enc * 0.0001f;
```

**量程：** int16 范围 ±32767 → ±3.2767 rad（±187°）。**覆盖所有关节的限位，不会溢出。**

**分辨率：** 0.0001 rad = 0.0057°。**远高于舵机的 0.088°/step，够用。**

**⚠️ 关节顺序必须用 §3.2 的【逻辑索引 A】（髋外摆×4 → 髋俯仰×4 → 膝×4），不要用 URDF 声明顺序。**

### 4.2 `mode` 枚举

| 值 | 名称 | 含义 |
|---|---|---|
| 0 | `MODE_IDLE` | 力矩卸载（机器人瘫软） |
| 1 | `MODE_STAND` | 保持站立（q_target 被忽略，用默认站姿） |
| 2 | `MODE_ACTIVE` | **正常跟踪 q_target** |
| 3 | `MODE_DAMP` | 阻尼模式（缓慢吸收冲击） |
| 4 | `MODE_ESTOP` | 紧急停止（缓慢趴下） |

**⚠️ `MODE_ACTIVE` 是唯一会跟踪 `q_target` 的模式。其他模式下 `q_target` 被忽略。**

### 4.3 `flags` 位域

| 位 | 名称 | 含义 |
|---|---|---|
| BIT0 | `FLAG_ENABLE` | 使能输出（0 = 只读不控） |
| BIT1 | `FLAG_RESET_ERR` | 清除舵机错误（自动清零） |
| BIT2 | `FLAG_REQ_STATUS` | 请求立即回一次 TEL_STATUS |
| BIT3 | `FLAG_REQ_CALIB` | 进入标定模式 |
| BIT4-7 | 保留 | 填 0 |

### 4.4 `TEL_FAST` (0x02) — STM32 → Pi

**⭐ 这是 RL 观测的主要来源。每周期都发。**

```
偏移  类型      字段          单位         长度  说明
────────────────────────────────────────────────────────────────
0     int16[12] q             0.0001 rad    24   关节位置（逻辑索引 A）
24    int16[12] qd            0.0001 rad/s  24   关节速度
48    int16[12] tau           0.001 N·m     24   关节力矩（从 Present Load 换算）
72    int16     quat_w        0.0001         2   四元数 w
74    int16     quat_x        0.0001         2   四元数 x
76    int16     quat_y        0.0001         2   四元数 y
78    int16     quat_z        0.0001         2   四元数 z
80    int16[3]  gyro          0.001 rad/s    6   角速度 x/y/z
86    int16     gait_sin      1/32767        2   ⭐ 步态相位 sin（见 §4.4.1）
88    int16     gait_cos      1/32767        2   ⭐ 步态相位 cos
90    uint16    cycle_cnt     1              2   ⭐ 100 Hz 周期计数（检测丢帧）
92    uint16    voltage       1 mV           2   电池电压
94    uint8     status        位域           1   见 §4.5
95    uint8     err_flags     位域           1   舵机错误汇总，见 §4.6
────────────────────────────────────────────────────────────────
LEN = 96   →  帧总长 = 103 字节
```

**⚠️ 结构体对齐警告：** 上面是按"紧凑字节流"定义的，**不是 C 结构体内存布局**。实现时必须用 `#pragma pack(1)` 或者逐字段 `memcpy`/指针偏移手工序列化。**直接把结构体指针强转成字节数组会因对齐填充而出错。**

**带宽核算：**

```
103 B × 10 位/B × 100 Hz = 103 kbps  →  占用 1 Mbps 的 10.3%   ✅ 宽裕
```

**四元数说明：**

```c
// STM32 侧：量化
int16_t qw_enc = (int16_t)(quat[0] * 10000.0f);   // ±1.0 → ±10000，不溢出

// Pi 侧：反量化 + 转重力向量
float qw = qw_enc * 0.0001f;
// ... 构造旋转矩阵 → 取第三列 → 机身系下的重力方向
```

**⚠️ 为什么要传四元数而不是直接传重力向量：** 四元数是完整姿态信息，Pi 侧可以按需算重力向量、欧拉角、旋转矩阵，而不用改协议。

### 4.4.1 ⭐ 步态相位（为什么由 STM32 产生）

**观测的第 45–46 维是步态相位 `sin/cos`。这两个量必须由 STM32 产生并发给 Pi。**

**理由：**

| # | 理由 |
|---|---|
| **1** | **唯一源头** —— 如果 Pi 和 STM32 各产生一份，数值会不一致 |
| **2** | **时钟精度** —— STM32 的 TIM 定时 100 Hz 精确到晶振级（±20 ppm）；Pi 5 的 Linux 用户态循环抖动 0.1~1 ms（±1~10%），**会累积相位误差** |
| **3** | **STM32 本来就是节拍源** —— 无论哪种时序模型，100 Hz 周期都由 STM32 发起 |
| **4** | **成本极低** —— 查正弦表或 `arm_sin_f32`，每周期 2 次 |

**⚠️⚠️ 相位算法必须与训练侧严格一致**（来自 `Sim/legged_gym/legged_gym/envs/rlcat/rlcat_env.py:104-106`）：

```c
// 训练侧原实现：
//   self.phase = (self.phase + self.dt * self.gait_freq) % 1.0
//   sin_p = sin(2*pi*phase)
//   cos_p = cos(2*pi*phase)
//
//   dt = 1/200（物理步长），gait_freq = 3.0 Hz
//   但观测是 decimation=2 之后组装的，所以每【控制周期】相位实际推进：
//       2 × (1/200) × 3.0 = 0.03

#define GAIT_FREQ_HZ      3.0f                       // ⚠️ 与 rlcat_config.py 的 gait_freq 一致
#define PHASE_STEP        (GAIT_FREQ_HZ / 100.0f)    // = 0.03  ← 每控制周期推进量

static float s_phase = 0.0f;
s_phase += PHASE_STEP;                 // 3.0/100 = 0.03
if (s_phase >= 1.0f) s_phase -= 1.0f;

float s = arm_sin_f32(2.0f * PI * s_phase);
float c = arm_cos_f32(2.0f * PI * s_phase);

int16_t gait_sin_enc = (int16_t)(s * 32767.0f);
int16_t gait_cos_enc = (int16_t)(c * 32767.0f);
```

**⚠️ 推导（为什么是 3.0/100 = 0.03，而不是 2×3.0/100）：**

```
训练侧：每个物理步推进 dt × gait_freq = (1/200) × 3.0 = 0.015
        decimation = 2 → 每 2 个物理步组装一次观测
        → 每【控制周期】相位推进 2 × 0.015 = 0.03   ✅

一个完整步态周期 = 1.0 / 0.03 ≈ 33.3 个控制周期 = 0.333 s
                  → 频率 = 3.0 Hz              ✅ 自洽
```

**⚠️ `cycle_cnt` 的用途：** Pi 用它检测丢帧（相邻帧的 `cycle_cnt` 应该 +1，否则说明丢了 N 帧）。它同时也是相位与帧的对应关系校验。

**⚠️ 相位在急停/标定/IDLE 时是否继续推进？** 建议**继续推进**（保持连续），只有 `MODE_ACTIVE` 才使用它。

## 5. CRC-16 实现

**算法：CRC-16/CCITT-FALSE**

```
多项式：0x1021
初值：  0xFFFF
输入反射：否
输出反射：否
异或输出：0x0000
```

**参考实现（查表法，占用 512 B Flash，速度最快）：**

```c
// 表在编译期生成，或放常量数组
static const uint16_t crc16_table[256] = { /* ... */ };

uint16_t crc16_ccitt(const uint8_t *data, uint16_t len) {
    uint16_t crc = 0xFFFF;
    while (len--) {
        crc = (crc << 8) ^ crc16_table[((crc >> 8) ^ *data++) & 0xFF];
    }
    return crc;
}
```

**如果 Flash 紧张，用位运算法（无表，慢 8 倍但省 512 B）：**

```c
uint16_t crc16_ccitt(const uint8_t *data, uint16_t len) {
    uint16_t crc = 0xFFFF;
    for (uint16_t i = 0; i < len; i++) {
        crc ^= (uint16_t)data[i] << 8;
        for (uint8_t b = 0; b < 8; b++) {
            crc = (crc & 0x8000) ? ((crc << 1) ^ 0x1021) : (crc << 1);
        }
    }
    return crc;
}
```

**⚠️ 两种实现必须产出相同结果。用标准测试向量验证：**

```
输入: "123456789" (9 字节 ASCII)
CRC-16/CCITT-FALSE 期望输出: 0x29B1
```

**⚠️ 这是必须写的单元测试。两端（STM32 和 Pi）都要用同一个测试向量验证。**

## 6. 接收状态机（两端都要实现）

```
        ┌──────────────────────────────────────┐
        │            WAIT_HEAD0                │
        │  读字节；== 0xAA → WAIT_HEAD1         │
        │           否则丢弃                     │
        └──────────────┬───────────────────────┘
                       │ 收到 0xAA
                       ▼
        ┌──────────────────────────────────────┐
        │            WAIT_HEAD1                │
        │  读字节；== 0x55 → WAIT_LEN           │
        │        == 0xAA → 留在本状态（容错）    │
        │        否则   → 回 WAIT_HEAD0         │
        └──────────────┬───────────────────────┘
                       │ 收到 0x55
                       ▼
        ┌──────────────────────────────────────┐
        │        收 LEN + SEQ + TYPE            │
        │  ⚠️ LEN > 128 → 丢弃，回 WAIT_HEAD0   │
        └──────────────┬───────────────────────┘
                       ▼
        ┌──────────────────────────────────────┐
        │         收 PAYLOAD (LEN 字节)         │
        │  ⚠️ 带超时（如 5 ms）超时则复位        │
        └──────────────┬───────────────────────┘
                       ▼
        ┌──────────────────────────────────────┐
        │            收 CRC16 (2 字节)          │
        └──────────────┬───────────────────────┘
                       ▼
        ┌──────────────────────────────────────┐
        │           校验 CRC                    │
        │  通过 → 分发到对应 TYPE 的处理函数      │
        │  失败 → err_count++，丢弃              │
        └──────────────────────────────────────┘
```

**⚠️ 三个必须的鲁棒性措施：**

| # | 措施 | 理由 |
|---|---|---|
| 1 | **`WAIT_HEAD1` 收到 `0xAA` 时留在本状态** | 处理 `AA AA 55` 这种重叠情况 |
| 2 | **LEN 上限检查（≤128）** | 防止错误 LEN 导致缓冲区溢出 |
| 3 | **整帧超时（5 ms）** | 防止收到半个帧后永久卡住 |

**⚠️ 第 3 点特别重要** —— 上位机崩溃/断开时，状态机必须能自己重置。

## 7. 通信时序

### 7.1 正常周期（请求-应答）

```
STM32                                        Pi
  │                                          │
  ├─ 采集 q/qd/tau/quat/gyro/voltage         │
  │                                          │
  ├─── TEL_FAST (103 B) ────────────────────→ │
  │                                          ├─ 组装观测向量 (50 维)
  │                                          ├─ 策略推理
  │                                          ├─ 动作 → 关节目标角
  │                                          │
  │ ←──── CMD_JOINT (38 B) ──────────────────┤
  │                                          │
  ├─ 解析 + 限幅                             │
  ├─ SyncWrite 下发舵机                       │
  │                                          │
  └─ 等待下个周期 (10 ms)                     │
```

**帧长修正：**

```
TEL_FAST  : LEN=96  →  总长 103 B
CMD_JOINT : LEN=31 → 总长 38 B
```

### 7.2 超时处理

```c
#define PI_CMD_TIMEOUT_MS   4      // 单周期内等指令的超时
#define PI_LINK_LOST_MS     30     // 连续多久没收到 = 失联
#define PI_LINK_ESTOP_MS    100    // 失联多久 = 强制急停
```

**⚠️ 但注意：STM32 不应该真的"阻塞等待"指令 —— 那会破坏 100 Hz 节拍。**

**推荐做法：**

```
周期开始时：
  if (有新指令) → 用它
  else          → 用【上一帧的指令】（保持）
                 并累计"无新指令"计数

如果真的等不到（>30 ms）→ 进入降级/急停
```

**⚠️ 这样周期永远不会被阻塞，节拍是确定的。代价是引入最多 1 个周期的延迟（10 ms）。**

### 7.3 ⚠️ 两种时序模型的取舍

| 模型 | 延迟 | 抖动 | 复杂度 |
|---|---|---|---|
| **A. 阻塞等待** | 低（~3 ms） | **高**（受 Pi 抖动影响） | 低 |
| **B. 不等，用上一帧** ⭐ | 高（~13 ms） | **零** | 低 |

**👉 建议先用模型 B** —— 100 Hz 下多 10 ms 延迟对 RL 影响不大（域随机化里本来就要加延迟随机化），但抖动小对训练稳定性帮助很大。

**⚠️ 如果发现延迟太大，再改成模型 A，但要给 Pi 的推理加时限保护。**

## 8. 安全性

### 8.1 链路失联检测

```c
// STM32 侧
void link_pi_poll(void) {
    // 解析接收到的字节
    // ...

    // 更新最后接收时间
    if (收到有效帧) {
        s_last_rx_ms = bsp_tick_ms();
        s_lost_count = 0;
    }

    // 失联判断
    uint32_t gap = bsp_tick_ms() - s_last_rx_ms;
    if (gap > PI_LINK_LOST_MS) {
        s_flags &= ~STAT_LINK_OK;
        if (gap > PI_LINK_ESTOP_MS) {
            app_enter_estop();     // 🔴 强制趴下
        }
    }
}
```

### 8.2 序列号丢帧检测

```c
// 收到 CMD_JOINT 时
uint8_t expected = (s_last_seq + 1) & 0xFF;
if (frame.seq != expected) {
    uint8_t lost = (frame.seq - expected) & 0xFF;
    s_seq_lost += lost;              // 累计丢帧
    // ⚠️ 不要因此做任何降级 —— 丢 1~2 帧是正常的
}
s_last_seq = frame.seq;
```

**⚠️ 丢帧上报给 Pi 即可，不要触发保护。** 只有**连续**大量丢帧才说明有问题。

### 8.3 指令合法化（⚠️ 防御性编程）

**永远不要相信上位机发来的数据：**

```c
void sanitize_cmd(pi_cmd_t *cmd) {
    // ① 模式合法性
    if (cmd->mode > MODE_ESTOP) cmd->mode = MODE_IDLE;

    // ② 逐关节限幅
    for (int i = 0; i < 12; i++) {
        float q = cmd->q_target[i];
        if (isnan(q) || isinf(q)) {
            cmd->q_target[i] = g_joints[i].q_min_rad;   // 或当前值
            continue;
        }
        if (q < g_joints[i].q_min_rad) cmd->q_target[i] = g_joints[i].q_min_rad;
        if (q > g_joints[i].q_max_rad) cmd->q_target[i] = g_joints[i].q_max_rad;
    }

    // ③ 限速：单周期最大变化量
    for (int i = 0; i < 12; i++) {
        float delta = cmd->q_target[i] - g_last_cmd[i];
        if (delta > MAX_DELTA_PER_CYCLE)  delta = MAX_DELTA_PER_CYCLE;
        if (delta < -MAX_DELTA_PER_CYCLE) delta = -MAX_DELTA_PER_CYCLE;
        cmd->q_target[i] = g_last_cmd[i] + delta;
        g_last_cmd[i] = cmd->q_target[i];
    }
}
```

**⚠️ NaN/Inf 检查是必须的** —— 如果 Pi 侧策略出现数值异常，发过来的就是 NaN，不加检查会让舵机乱转。

**⚠️ 限速（`MAX_DELTA_PER_CYCLE`）是最后一道防线** —— 即使策略给出跳变的目标角，也不会让机器人瞬间抽搐。

**建议值：`MAX_DELTA_PER_CYCLE = 0.15 rad`（约 8.6°/周期 = 860°/s）。**

## 9. 树莓派端参考实现（伪代码）

```python
import serial, struct, time

HEAD = b'\xAA\x55'
TYPE_CMD_JOINT = 0x01
TYPE_TEL_FAST  = 0x02

def crc16(data: bytes) -> int:
    crc = 0xFFFF
    for b in data:
        crc ^= b << 8
        for _ in range(8):
            crc = ((crc << 1) ^ 0x1021) & 0xFFFF if crc & 0x8000 else (crc << 1) & 0xFFFF
    return crc

def pack(msg_type: int, seq: int, payload: bytes) -> bytes:
    body = bytes([len(payload), seq, msg_type]) + payload
    return HEAD + body + struct.pack('<H', crc16(body))

def unpack(buf: bytes):
    """返回 (type, seq, payload) 或 None"""
    if len(buf) < 7 or buf[0] != 0xAA or buf[1] != 0x55:
        return None
    ln = buf[2]
    if len(buf) < 7 + ln:
        return None
    body = buf[2:5+ln]
    crc_rx = struct.unpack('<H', buf[5+ln:7+ln])[0]
    if crc16(body) != crc_rx:
        return None
    return buf[4], buf[3], buf[5:5+ln]

def make_cmd_joint(q_target, mode=2, flags=1, seq=0) -> bytes:
    """
    CMD_JOINT 负载构造（LEN = 31）

    字节布局（见 §4.1）：
        [0]      uint8   mode
        [1]      uint8   flags
        [2:26]   int16×12 q_target     (0.0001 rad/单位，小端)
        [26]     uint8   reserved
        [27:29]  int16   kp_scale      (0.01/单位，小端)
        [29]     uint8   led
        [30]     uint8   reserved2
    """
    assert len(q_target) == 12, len(q_target)

    payload  = struct.pack('<BB', mode, flags)                        # 0..1   (2 B)
    payload += b''.join(struct.pack('<h', int(round(q / 0.0001)))     # 2..25  (24 B)
                        for q in q_target)
    payload += struct.pack('<B', 0)                                   # 26     (1 B) reserved
    payload += struct.pack('<h', 100)                                 # 27..28 (2 B) kp_scale = 1.00
    payload += struct.pack('<B', 1)                                   # 29     (1 B) led
    payload += struct.pack('<B', 0)                                   # 30     (1 B) reserved2

    assert len(payload) == 31, "payload 应为 31 字节，实际 %d" % len(payload)
    return pack(TYPE_CMD_JOINT, seq, payload)

def parse_tel_fast(payload: bytes) -> dict:
    """
    TEL_FAST 负载解析（LEN = 96，见 §4.4）

    字节布局：
        [0:24]   int16×12 q          (0.0001 rad/单位)
        [24:48]  int16×12 qd         (0.0001 rad/s)
        [48:72]  int16×12 tau        (0.001 N·m)
        [72:80]  int16×4  quat        (w, x, y, z；0.0001/单位)
        [80:86]  int16×3  gyro        (0.001 rad/s)
        [86:88]  int16    gait_sin    (1/32767 单位)   ⭐
        [88:90]  int16    gait_cos    (1/32767 单位)   ⭐
        [90:92]  uint16   cycle_cnt   (100 Hz 周期计数) ⭐
        [92:94]  uint16   voltage     (mV)
        [94]     uint8    status
        [95]     uint8    err_flags
    """
    assert len(payload) == 96, "TEL_FAST 负载应为 96 字节，实际 %d" % len(payload)

    q     = struct.unpack_from('<12h', payload, 0)
    qd    = struct.unpack_from('<12h', payload, 24)
    tau   = struct.unpack_from('<12h', payload, 48)
    quat  = struct.unpack_from('<4h',  payload, 72)
    gyro  = struct.unpack_from('<3h',  payload, 80)
    sin_p = struct.unpack_from('<h',   payload, 86)[0]
    cos_p = struct.unpack_from('<h',   payload, 88)[0]
    cyc   = struct.unpack_from('<H',   payload, 90)[0]
    volt  = struct.unpack_from('<H',   payload, 92)[0]
    st    = payload[94]
    err   = payload[95]

    return dict(
        q=[v * 0.0001 for v in q],
        qd=[v * 0.0001 for v in qd],
        tau=[v * 0.001 for v in tau],
        quat=[v * 0.0001 for v in quat],          # (w, x, y, z)
        gyro=[v * 0.001 for v in gyro],
        gait_sin=sin_p / 32767.0,
        gait_cos=cos_p / 32767.0,
        cycle_cnt=cyc,
        voltage_mv=volt,
        status=st,
        err_flags=err)

# ============================================================
# 47 维观测组装（Pi 侧）
# ============================================================
def quat_to_gravity(quat):
    """四元数 (w,x,y,z) -> 机身系下的重力方向单位向量（3 维）"""
    import math
    w, x, y, z = quat
    # 旋转矩阵第三行 = 机身系下的「上」方向；重力取其负
    # R[2][:] = [2(xz - wy), 2(yz + wx), 1 - 2(x² + y²)]
    gx = -2.0 * (x * z - w * y)
    gy = -2.0 * (y * z + w * x)
    gz = -(1.0 - 2.0 * (x * x + y * y))
    n = math.sqrt(gx*gx + gy*gy + gz*gz)
    return [gx / n, gy / n, gz / n]


def build_observation(tel, cmd, last_action, q_default=None):
    """
    组装 47 维观测（与 legged_gym 的 compute_observations 位对齐）

    ⚠️ 每一维的位置必须与 Sim/legged_gym/.../rlcat_env.py 严格一致
    """
    if q_default is None:
        q_default = [0.0] * 12          # 项目里 q_default 全为 0

    obs = []
    obs += quat_to_gravity(tel['quat'])            #  0- 2  重力向量（机身系）
    obs += [v * 0.25 for v in tel['gyro']]         #  3- 5  角速度 ×0.25
    obs += [cmd['vx'], cmd['vy'], cmd['wz']]       #  6- 8  速度指令
    obs += [tel['q'][i] - q_default[i] for i in range(12)]   #  9-20  关节位置（相对 q_default）
    obs += [v * 0.1 for v in tel['qd']]            # 21-32  关节速度 ×0.1
    obs += [v * 4.0 for v in last_action]          # 33-44  上一帧动作 ×4.0
    obs += [tel['gait_sin'], tel['gait_cos']]      # 45-46  步态相位 ⭐ 来自 TEL_FAST

    assert len(obs) == 47, "观测应为 47 维，实际 %d" % len(obs)
    return obs
```
