## 0. 两个必须先说的发现

### ⚠️ 发现 1：文档推荐的检查点是**失败的那次训练**

45-linux-tasks.md §2.1 说：

> `Oct06_03-15-34_` 是后起的训练，通常是更优的那次。

**这条假设是错的。** `Oct06_03-15-34_` 正是本项目**第 8 轮实验**，我把它判定为失败并放弃了。实测三个候选的对比：

| run | 峰值平均回报 | 末期 episode 长度 | 末期 tracking(原始) | 判定 |
|---|---|---|---|---|
| `Oct06_02-58-05_`（第 7 轮） | 40.67 | 1909 | 0.801 | 可用，但中高速欠响应（误差 0.134/0.162） |
| **`Oct06_03-15-34_`（第 8 轮）** | **72.11 ← 全表最高** | **891 ← 会摔** | 0.547 | ❌ **失败** |
| **`Oct06_03-32-41_`（第 9 轮）** | 31.82 | **2002 ← 跑满** | 0.784 | ✅ **全部验收达标** |

**"峰值回报最高"的恰恰是坏的那个。** 原因：第 8 轮把 `tracking_lin_vel` 权重提到 6.0，训练后期机器人开始摔 —— episode 从 2002 掉到 891，惩罚累积变少，**平均回报反而被推高了**。

> 📌 **通用教训**：`Mean reward` 在不同 episode 长度下**不可比**。判断模型好坏必须
> **同时看 `Mean episode length`**；长度掉下来就是训练在变差，此时 reward 数字再高也没意义。

**⇒ 本次导出用的是 `Oct06_03-32-41_/model_500.pt`（第 9 轮，iter 499）。**
它经过完整的固定指令验收：−0.3 ~ +0.5 m/s 全段跟踪误差 0.060~0.099，零摔倒，左右占空比差 0.08~0.14。

### ⚠️ 发现 2：`export_policy.py` 有个 bug，"唯一不循环的检查"被静默跳过

`verify_with_rsl_rl()` 第 302 行原文：

```python
hidden = [W.shape[0] for W, _ in layers[1:]]      # ❌ 错
```

`layers[1:]` 包含了**输出层**，于是把输出维度 12 也当成隐藏层，构造出 `47→128→64→12→12` 的错误网络，`load_state_dict` 必然失败 → 异常被 `except` 吞掉 → **这段检查静默跳过**。

而 45-linux-tasks.md §2.4 明确说这条是"**唯一不循环的检查**"（前两个对比都建立在"层顺序假设"上，假设错了会一致地错）。**它被跳过 = 实际上没有独立验证。**

**已修复为 `layers[:-1]`**，并在旁边加了注释说明原因。修复后：

```
 ---- 可选：用 rsl_rl 真实 ActorCritic 复核 ----
   与 rsl_rl 真实 actor 的最大相对误差 = 0.000e+00
   ✅ 层顺序假设正确
```

## 5. L2 / L4 无法完成的原因

这两项需要**树莓派上的 shell 访问**（`ssh <pi>`）。当前 Linux 机器上：

```bash
$ ssh <pi> ...        # 没有可用的 Pi 地址/密钥
```

**L2（依赖 + CPU governor）和 L4（Pi 侧测试）必须在 Pi 上执行**，我这边做不到。
L2/L4 的命令原文在 45-linux-tasks.md §3 和 §5，照着跑即可 —— 它们都不依赖本次导出。

## 6. 一个额外的提醒：部署前必须补驱动器延迟

`45-linux-tasks.md` §9 提到"机器人必须在地面上稳定站住"这个前置条件。**还有一个同等重要的：**

**现在仿真里的舵机是"理想伺服"** —— 给了目标角度下一个物理步就到位。真机上：
- 总线 SyncWrite 约 1 ms
- 舵机内部 PID 响应
- 总延迟约 **1~3 个控制周期（10~30 ms）**

**后果**：真机上会震荡，而仿真里完全看不出来。建议在仿真里加一个动作延迟队列并纳入域随机化（每次 reset 随机 1~3 步），重训一版再部署。

这也和 45-linux-tasks.md 里"至今所有测试都是吊起的"呼应 —— 吊起时机器人不承重，延迟的影响被掩盖了，**落地后才会暴露**。
