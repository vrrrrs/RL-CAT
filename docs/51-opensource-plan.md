## 0 · 先给判断

### 0.1 这个项目值得开源，但卖点不是"算法"

| 卖点 | 稀缺性 | 说明 |
|---|---|---|
| **完整闭环** | 🔴 高 | 机械 + 电子 + 固件 + 树莓派 + 强化学习，**一条链全开源**的四足项目很少 |
| **25 个坑的根因分析**（`docs/49`） | 🔴 **很高** | 绝大多数开源项目只有"怎么用"，**没有"我们踩了什么、为什么"** |
| **可量化的验收方法**（`stand_test.py` 4 项指标） | 🟡 中 | "站住了"变成"到位 1.23°、漂移 0.00°"，比"能站稳"有说服力 |
| **1370 项无硬件测试** | 🟡 中 | 别人能 `run_checks.sh` 立刻验证，降低参与门槛 |
| 算法新颖性 | ⬜ 无 | 用的是 PPO + 标准 legged_gym 流程 |

**⇒ 定位建议：** **"一个完整、可复现、且诚实地记录了失败的四足机器人平台"**，而不是"一个新算法"。

### 0.2 三个阻塞项（不解决不能发）

| # | 阻塞项 | 严重性 |
|---|---|---|
| **B1** | **许可与第三方边界**没说清（legged_gym BSD-3 / isaacgym 专有 / 厂商 SDK） | 🔴 法律风险 |
| **B2** | **硬编码的个人环境**：`~/` 30+ 处、`C:\Users\<user name>\` 16+ 处 | 🔴 **别人 clone 下来跑不起来** |

**⚠️ B2 比 B3 更重要** —— 隐私只影响自己，**路径写死会让项目"看起来能跑、实际跑不了"，这是开源项目最常见的死因。**

## 1 · 许可选择（**需要你决定**）

### 1.1 三层许可（推荐组合）

| 层 | 推荐 | 备选 |
|---|---|---|
| **代码**（固件 / Pi / 训练脚本） | **Apache-2.0** | MIT（更宽松）/ GPL-3.0（更严格） |
| **硬件**（CAD / 电路 / URDF） | **CERN-OHL-S-2.0** | CERN-OHL-W（弱互惠）/ CC-BY-SA-4.0 |
| **文档** | **CC-BY-4.0** | CC-BY-SA-4.0 |

### 1.2 我的推荐理由

**代码选 Apache-2.0 而不是 MIT：**
- 多了**显式专利授权**和**专利报复条款** —— 机器人涉及舵机控制、步态，可能被别人申请专利
- 要求标注修改 —— 对"fork 后声称是自己做的"有一定约束
- 仍然允许商业使用（降低企业用户顾虑）

**⇒ 如果你更想要"最大传播"，选 MIT；如果担心"被人拿去申请专利再告你"，选 Apache-2.0。**

**硬件选 CERN-OHL-S：**
- 专为开源硬件写的，**明确覆盖"制造"这个行为**（CC 系列对硬件是模糊的）
- `-S`（强互惠）= 别人改了设计必须同样开源；`-W`（弱）= 只要求文件层面
- **⚠️ 如果你希望别人能做商业产品（卖机器人），选 `-W` 或 CC-BY-SA**

### 1.3 ⚠️ 第三方边界（**必须写进 NOTICE**）

| 组件 | 许可 | 我们怎么处理 |
|---|---|---|
| **legged_gym**（`Sim/legged_gym`） | 见其 `LICENSE`（BSD-3 系） | **保留原 LICENSE 与版权头**，在 NOTICE 里声明是衍生作品 |
| **Isaac Gym** | 🔴 **NVIDIA 专有 EULA，不可再分发** | **只 `import`，不复制**；README 明确要求用户自行向 NVIDIA 申请 |
| **STM32 HAL/CMSIS** | BSD-3（ST） | 已 `.gitignore`；README 说明用 CubeMX 重新生成 |
| **WitMotion SDK**（`reference/`） | 🔴 厂商资料 | 已 `.gitignore`，**永不发布** |
| **Waveshare / Feetech 资料** | 厂商 | 同上 |
| **Isaac Gym 示例资产**（`anymal_b` 等 mesh） | NVIDIA 资产 | 已 `.gitignore` |

**⚠️ 一条底线：不发布任何"别人没授权我们再分发"的二进制。**

## 2 · 清场（P0，阻塞项）

### 2.1 B2 · 硬编码路径（**优先做，因为它影响可用性**）

**现状：**

| 位置 | 问题 | 数量 |
|---|---|---|
| `Sim/RL/scripts/*.py` | `ASSET_ROOT = "$RLCAT_ROOT/urdf"` 等 | 10 个脚本 |
| `Sim/RL/scripts/env.sh` | `export RLCAT_ROOT="$RLCAT_ROOT"` | 1 |
| `Sim/RL/*.md` | 文档里全是 `~/...` 的 `cd` 命令 | 5 份 |
| `pi/*.md` | SSH 私钥绝对路径、`pi@169.254.100.2` | 3 份 |
| `firmware/esp32/*` | `C:\Users\<user name>\...`（说明 SUBST 绕过的原因） | 3 处 |
| `docs/36,38,42,90` | 同上 | 4 份 |

**处理方式：**

```
① 脚本改为"从环境变量读，缺省用相对路径"
     env.sh:  export RLCAT_ROOT="${RLCAT_ROOT:-$(cd "$(dirname "$0")/.." && pwd)}"
     脚本:    ASSET_ROOT = os.environ.get("RLCAT_URDF", os.path.join(ROOT, "urdf"))

② 文档里的绝对路径改成占位符
     $RLCAT_ROOT        →  $RLCAT_ROOT
     C:\Users\<user name>\...      →  <repo>
     ~/RL-CAT/pi         →  ~/RL-CAT/pi

③ 保留"为什么这么做"的解释（SUBST 绕过空格等），只去掉个人信息
     ⇒ 这些解释是本项目有价值的工程内容，不要删
```

### 2.2 B3 · 口令与个人信息

| 项 | 处理 |
|---|---|
| `RLCA_AP_PASSWORD "rlcat1234"` | 改为构建期可覆盖的弱默认，README 第一条警告"**改掉它**" |
| SSH 私钥路径（`pi/开发方式.md`） | 改成 `<your-key>` 占位 |
| 真实姓名 `<name>` | 🟡 **建议保留**（作者署名，开源项目正常）—— 但**桌面路径要改** |
| `169.254.100.2` | ✅ 保留（是配置示例，不是秘密） |

## 5 · CI 方案（本项目的隐藏优势）

**⚠️ 很多机器人项目没法做 CI，因为依赖硬件。这个项目可以：**

| 测试 | 能否无硬件跑 | CI 命令 |
|---|---|---|
| 固件主机单测（7 套 1370 项） | ✅ | `gcc` 编译 + 运行 |
| Pi 侧 `run_checks.sh` | ✅ | `python3` 即可 |
| 策略对拍（`rl_policy.py --selftest`） | ✅ | 纯 numpy |
| 固件构建 | 🟡 | `arm-none-eabi-gcc` + 转 Makefile（现在只支持 Keil） |
| 训练环境 | ❌ | 需要 Isaac Gym（专有，CI 跑不了） |

**建议的 `ci.yml`：**

```yaml
jobs:
  host-tests:      # Ubuntu + gcc：firmware/tests 7 套
  pi-tests:        # Ubuntu + python3：pi/run_checks.sh
  policy-verify:   # 策略对拍仿真轨迹（验证观测布局没被改坏）
```

**⚠️ `policy-verify` 这一项特别有价值** —— 它保证"任何人都不会误改观测布局而不自知"。

**⚠️ 要补一个 Makefile 或 CMake 才能让固件在 CI 里构建**（现在只有 Keil 工程）。这是一个**中等工作量**（半天）但有长期收益的改动。
