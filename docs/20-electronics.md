## 1. 电源架构

### 1.1 总体

```
3S1P 18650 电池（9.0 – 12.6 V）
   │
   ├── 16 AWG 粗线 ──→ 12 个舵机 V（全部并联）⭐ 绕过控制板
   ├── 16 AWG 粗线 ──→ 12 个舵机 G（与控制板共地）
   ├── 细线（20~50 mA）──→ 舵机控制板 DC 输入
   ├── Mini560 降压 5V/5A ──→ PCB ──→ USB-C ──→ 树莓派 5
   └── 分压器 (100k/20k) ──→ STM32 PA0（电池电压监测）
```

### 1.2 ⚠️ 为什么供电要绕过控制板

**Waveshare Bus Servo Adapter (A) 有 5 A 总电流上限，但 12 个舵机堵转需要 32 A。**

**解决方式：**

```
舵机动力 → 从电池经 16 AWG 粗线【直接并联】，不经过控制板
控制板   → 只用细线供它自身工作的 20~50 mA
信号     → 走控制板的信号输出（D 线）
```

**⚠️ 代价：控制板上的电流检测不再反映舵机总电流。** 但本项目不做电流采样（已决策）。

### 1.3 电池

| 参数 | 值 |
|---|---|
| 类型 | **3S1P 18650** |
| **放电能力要求** | **≥25 A 连续**（Molicel P26A / Sony VTC5A / Molicel P28A） |
| 电压范围 | 9.0 – 12.6 V |
| 容量 | 约 27.8 Wh，续航约 14 min |

**⚠️ 不能用普通 15–20 A 电芯**（VTC6、30Q、25R）—— 12 舵机堵转电流会超出其能力。

**⚠️ 建议加一个 3S 低压蜂鸣器报警器**（接平衡头，¥5）作为总电压 ADC 之外的备份 —— 它能捕捉单节不平衡，而总电压采样不能。

### 1.4 电池电压检测

**方案：STM32 内部 ADC + 外部分压（全部直插元件，便于手焊）**

| 元件 | 值 | 说明 |
|---|---|---|
| R1 | **100 kΩ 1% 金属膜** | 上臂 |
| R2 | **22 kΩ 1% 金属膜** | 下臂 |
| C1 | **100 nF 陶瓷（104）** | 滤波，直插 |
| 接法 | 电池 + → R1 → PA0 → R2 → GND | 分压比 = (100+20)/20 = **6.000** |

**⚠️ 两步标定必须做：**

```
第一步：万用表量 STM32 模块 3.3 V 引脚的真实值 → 填 ADC_VREF_MV
        （标称 3300 mV，实际可能 3260~3340）
第二步：对比固件读数与万用表量的电池电压 → 微调分压比
        目标：误差 < 50 mV
```

**电压阈值分级：**

| 电压 | 级别 | 动作 |
|---|---|---|
| > 10.5 V | 正常 | — |
| ≤ **10.5 V** | L1 警告 | LED 慢闪 + 上报 |
| ≤ **9.9 V** | L2 | 上报 + 限制动作幅度 |
| ≤ **9.3 V** | L3 强制 | **卸载力矩 → 趴下** |

### 1.5 树莓派 5 供电

**⚠️ 不要直接给 GPIO 的 5V 引脚供电（会绕过 Pi 的保护电路）。**

```
Mini560（5V/5A 降压）→ PCB → USB-C 母座（CC 引脚 2× 5.1 kΩ 下拉）→ C-to-C 线 → Pi 5
```

**⚠️ 上电后实测：`vcgencmd get_throttled`，看是否出现 `0x50000`（欠压标志）。**

### 1.6 ⚠️ 接地（比电容重要得多）

```
电池 − ──┬── 舵机 G（全部并联）
         ├── 控制板 GND
         ├── STM32 GND
         └── Pi GND
```

**⚠️ 必须单点共地或星形接地，避免大电流回路把地电位抬高。**

**⚠️ 24 A 电流下的地弹跳：用示波器量逻辑地对电池负极的压差，应 < 50 mV。**

## 2. 主控与通信

### 2.1 三路 UART 分配（F103C8 的 3 个 USART 刚好用尽）

| 外设 | 引脚 | 波特率 | 连接 | 接线方式 |
|---|---|---|---|---|
| **USART1** | PA9 (TX) / PA10 (RX) | **500 kbps** | 树莓派 5 | **交叉**（TX→RX、RX→TX） |
| **USART2** | PA2 (TX) / PA3 (RX) | **1 Mbps** | 舵机控制板 | **直连**（RX→RX、TX→TX）⚠️ |
| **USART3** | PB10 (TX) / PB11 (RX) | **115200** | ESP32-C3 无线 | 交叉 |

**⚠️ USART2 的接线与控制板跳线：**

```
跳线必须在【A 位】（A = UART 控制，B = USB 控制）
接线是【直连】：RX→RX、TX→TX
依据：https://docs.waveshare.com/Bus_Servo_Adapter_A/Product-Wiring-Example
      "The connection must be RX-RX, TX-TX correspondingly.
       At this time, the jumper cap ... must be in the A position."
```

**⚠️ 两条链路的接法不同，不要搞混。**

### 2.2 为什么选 100 Hz 控制环

**不是 200 Hz，也不是 1 kHz。理由：**

| 因素 | 说明 |
|---|---|
| **总线时间** | 12 舵机一次 SyncWrite + SyncRead 约 2.5 ms，100 Hz 周期（10 ms）占用 25% |
| **接线上限** | 单总线带 12 舵机时，读一轮的串行时间决定频率上限 |
| **RL 需求** | 策略 50~100 Hz 完全够用 |
| **舵机内环** | 舵机内部有 PID 内环，扰动抑制不依赖外环带宽 |

### 2.3 舵机控制板

| 项 | 值 |
|---|---|
| 型号 | **Waveshare Bus Servo Adapter (A)**，SKU 25514 |
| 尺寸 | 42 × 33 mm |
| 输入电压 | 9 – 12.6 V |
| **电流上限** | **5 A**（⚠️ 已被外部分流绕过） |
| 板载稳压 | 无 |
| USB 桥 | CH343 |
| 信号接口 | 2 个相同接口，共用一条 D 线 |

## 3. IMU 与传感器

### 3.1 JY901P

| 项 | 值 |
|---|---|
| 接口 | **软件 I2C**（PB8 = SCL，PB9 = SDA） |
| **⚠️ 关键配置（两个旋钮，别只调一个）** | **不是"波特率"** —— I2C 器件没有波特率。要配的是：<br/>① **带宽 `BANDWIDTH`@0x1F = 2（98 Hz）** —— 内部传感器采样带宽，**上位机最高只到 98 Hz**，选它就对了<br/>② **输出速率 `RRATE`@0x03 = 9（100 Hz）** —— 寄存器上报频率。⚠️ **默认是 6（仅 10 Hz）**，不改的话 100 Hz 控制环会把同一份姿态读 10 次，观测呈阶梯状、策略会抖 |
| **⚠️⚠️ I2C 数据是【小端】** | 手册没写字节序，**实测确认是小端**（低字节在前）。早期固件按大端解析 → 姿态全错、加速度模 15.6 g。详见 handover §5.7 |
| 算法 / 安装方向 | 九轴（`AXIS6`=0）+ 水平（`ORIENT`=0）—— 与固件假设一致。⚠️ 无磁力计时航向角无绝对参考，**不要拿 yaw 当绝对航向** |
| **SCL 频率目标** | **100~400 kHz**（用示波器量，不要靠数 `__NOP()` 猜） |
| 融合 | **模块内部完成**，MCU 只需读结果（MCU 负载 ≈ 0） |
| 上拉 | **外部 4.7 kΩ 到 3.3 V**（必须装） |

**⚠️ 读帧时间预算：**

```
读四元数(8B) + 角速度(6B) = 14 B
加地址与寄存器开销约 20 B
@ 400 kHz → 约 0.45 ms   ✅ 推荐
@ 100 kHz → 约 1.8 ms   （占 100 Hz 周期的 18%，可接受但偏多）
```

**⚠️ "输出速率"是关键：** 若模块只按 10 Hz 更新而控制环按 100 Hz 读，会读到同一份数据 10 次 —— 姿态观测变阶梯状，策略会抖。**必须在模块上把输出速率提到 ≥100 Hz。**

**⚠️ 完整说明见 [`firmware/doc/固件设计书.md`](../firmware/doc/固件设计书.md) §5.4。**

**⚠️ 软件 I2C 注意事项：**

- PB8/PB9 已配成**开漏（OD）+ 高速**
- **开漏模式下不要用 `HAL_GPIO_WritePin` 输出高电平驱动** —— 靠外部上拉
- 时序需加延时，72 MHz 下 `__NOP()` 数量要按实测调整

### 3.2 未采用的传感器

| 传感器 | 未采用原因 |
|---|---|
| **足底开关** | v1 未安装；改用舵机 `Present Load` 判断触地 |
| **关节力矩传感器** | 舵机自带 `Present Load` 反馈，够用 |
| **电流采样** | 已决策不做 |
| **原始 IMU + MCU 端 Mahony 融合** | JY901P 内部已融合，MCU 负载 ≈ 0，无需自算 |

## 4. 无线模块（ESP32-C3）

**接 USART3（PB10/PB11），115200。**

**⚠️ 波特率 2026-10-10 由 921600 改为 115200**（低频调试通道，可靠性优先）。
随之有两条必须同时成立的约束：STM32 侧**发送必须非阻塞（中断）**、
镜像**必须降频到 10 Hz** —— 否则会拖垮 100 Hz 控制环，破坏 RL 的
decimation=2 时序契约。理由与实测数据见
[`32-esp32-bridge.md`](32-esp32-bridge.md) §1 与 [`36-esp32-plan.md`](36-esp32-plan.md) §2.2。

| 项 | 值 |
|---|---|
| 型号 | ESP32-C3 开发板 |
| 固件 | **自写 UART↔WiFi 透传（ESP-IDF）**，不用 ESP-AT（见 [`32-esp32-bridge.md`](32-esp32-bridge.md)） |
| 使用方式 | **AP 模式 + TCP Server** —— 笔记本连上热点后用 TCP 工具收发，PC 侧零驱动 |
| **接口接线** | **交叉**（ESP32 TX → PB11，ESP32 RX ← PB10） |
| 定位 | ⭐ **未接 Pi 5 时的无线调试通道**；接 Pi 后只做遥测 + 硬急停 |

### 4.1 ⚠️ 供电（**阻塞级待确认项**）

**设计要求：独立 3.3 V，≥800 mA。**

**理由：WiFi 发射峰值 500 mA。挂在 STM32 核心板 LDO（AMS1117，约 300 mA）上会拉垮 3.3 V，导致 STM32 复位。**

**⚠️ 但实测原理图显示三个器件挂在同一条 3.3 V 上：**

```
      独立 3.3V 降压
              │
              ├──→ STM32
              ├──→ JY901P
              └──→ ESP32-C3
```

**两种可能，必须实测区分：**

| 情况 | 后果 |
|---|---|
| **A. 该降压模块本身 ≥800 mA** | ✅ 没问题 |
| **B. 该降压能力不足** | ❌ **WiFi 发射时 3.3 V 塌陷 → STM32 复位** |

**⚠️ 测试方法：**

```
① 让 ESP32 持续发射 WiFi（例如 iperf 打流）
② 示波器量 3.3 V 轨的纹波与跌落
③ 同时监控 STM32 是否复位（看心跳 LED 是否重启）
判据：3.3 V 跌落 < 100 mV，且 STM32 不复位
```

**⚠️ 必做的硬件措施：**

| # | 措施 |
|---|---|
| 1 | **ESP32 的电源输入加 100 µF 电解 + 100 nF 瓷片**（WiFi 尖峰必须靠这个） |
| 2 | **天线净空** —— 板载天线周围留空，不要贴金属 |

### 4.2 ⚠️ UART3 是否双重负载（**阻塞级待确认项**）

**原理图里有 U6（标 ESP32）和 U9（标 ESP32-C3）同时用 TX3/RX3。**

**⚠️ 若是两个独立接口，两个 TX 会互相打架（一个推高、一个拉低）—— 方案无法落地。**

**必须确认：**

```
□ 是同一个接口的两种画法（则无碍）
□ 还是两个独立器件（则必须二选一，或加缓冲）
```

**⚠️ 详细的固件设计见 [`32-esp32-bridge.md`](32-esp32-bridge.md)。**
