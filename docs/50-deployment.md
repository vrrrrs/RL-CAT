## 2. 部署前必须完成的准备

### 2.1 仿真侧

```
□ 策略通过仿真压力测试（参数扰动、初始状态扰动、外力推挤）
□ 策略通过延迟扫描测试（找出崩溃阈值）
□ 域随机化已覆盖关键参数（质量、摩擦、PD 增益、延迟、传感器噪声）
□ 观测归一化参数已固化（不能依赖训练时的 running statistics）
```

### 2.2 固件侧

```
□ 三个 UART 全部调通（舵机总线 / 树莓派链路 / ESP32）
□ servo_bus 通过「连续 1000 轮零错误」验收
□ 关节零点已标定并存入 Flash
□ 安全机制全部验证（低压 / 超温 / 失联）
□ 急停按钮就位
```

### 2.3 映射对齐（⚠️ 最容易错）

```
**关节顺序（2026-10-18 用两个独立判据确认）**

```
协议 / 固件 / config.py  = group-major（我们的外部接口一律用它）
    lf_hip, lb_hip, rf_hip, rb_hip, lf_thigh, lb_thigh, rf_thigh, rb_thigh,
    lf_calf, lb_calf, rf_calf, rb_calf

训练侧 / 策略输出         = leg-major（Isaac Gym 按 URDF 的 <joint> 出现顺序）
    lf_hip, lf_thigh, lf_calf, lb_hip, lb_thigh, lb_calf,
    rf_hip, rf_thigh, rf_calf, rb_hip, rb_thigh, rb_calf

换算（已在 pi/rl_policy.py 里实现，调用者无需关心）:
    PERM_PROTO_TO_TRAIN = [0, 3, 6, 9, 1, 4, 7, 10, 2, 5, 8, 11]
    PERM_TRAIN_TO_PROTO = [0, 4, 8, 1, 5, 9, 2, 6, 10, 3, 7, 11]
```

**两个独立证据：**

| 判据 | leg-major | group-major |
|---|---|---|
| 用实机 URDF 限位衡量 1000 步仿真回放 | **544 度·步** | 18384 度·步（34×） |
| hip 组形状（真实限位 [0°,40°]：窄且单向） | span **39.8°**、负值 **0.1%** ✅ | span 83.1°、负值 26.1% ❌ |

**⚠️ 旧版本这里写的是 `A2C = [3,0,9,6,4,1,10,7,5,2,11,8]`，它把 `lf_hip` 映射到 `lb_hip` 的关节 —— 与上述两个判据都矛盾，已废弃。**
**⚠️ 顺序搞错的后果不是"精度下降"，而是每条动作发到错误的关节 ⇒ 上机立刻摔。**
□ 观测向量的每一维，固件与仿真必须【位对齐】
□ 动作缩放一致（0.25 rad/单位）
□ 关节限位：⚠️ **未解决的设计分歧** —— 固件现在用训练 URDF 的 90°，
   而实机 URDF 只有 30°。见 docs/48-sim2real-gaps.md §G1。
```

## 3. 上真机的顺序

**⚠️ 严格按此顺序，每步都验证后再进下一步。**

| 步骤 | 做什么 | 判据 |
|---|---|---|
| **1** | 机器人**吊起**（或用支架撑住，腿悬空） | |
| **2** | 跑策略，观察关节运动 | 和 sim 里相同指令下的关节运动一致 |
| **3** | **⚠️ 校验关节方向与偏置** | 这一步就能发现方向反了、偏置错了 |
| **4** | 落地，先**站着不动** | 能稳定站立 |
| **5** | **低速小范围**行走 | 不摔 |
| **6** | 逐步放开速度与范围 | |

**⚠️ 第 3 步是"吊起测试"的核心价值 —— 在无风险状态下暴露映射错误。**

## 4. 安全机制（⚠️ 必须有）

| 机制 | 实现位置 | 说明 |
|---|---|---|
| **急停按钮** | 硬件 | 直接切断舵机动力 |
| **姿态保护** | STM32 | roll/pitch 超阈值 → 立即趴下 |
| **低压保护** | STM32 | 10.5V 警告 / 9.9V 建议停 / 9.3V 强制趴下 |
| **超温保护** | 舵机自带 + STM32 读回 | >70 °C |
| **过流保护** | 舵机自带 | >2A 持续 2s 切断 |
| **链路失联保护** | STM32 | 30 ms 降级 / 100 ms 强制趴下 |
| **软启动** | STM32 | 上电先慢慢站起，不要瞬间给满力矩 |

**⚠️ 所有保护都必须在 STM32 上独立完成，不能依赖树莓派。**

## 5. 系统辨识（sim-to-real 的关键）

**⚠️ 这一步决定 sim-to-real 的成败，也是域随机化范围的依据。**

### 5.1 要测什么

| # | 实验 | 测什么 | 怎么测 |
|---|---|---|---|
| **1** | **阶跃响应** | PD 实际增益、上升时间、超调 | 给单关节阶跃位置指令，记录 `Present Position` 曲线 |
| **2** | **正弦扫频** | 频响、带宽、相位滞后 | 不同频率的正弦指令，测幅相 |
| **3** | **纯延迟** | 从下发到位置开始变化的延迟 | 从阶跃响应的起始段读 |
| **4** | **力矩-电流关系** | 验证 Kt | 吊起腿，测不同 `Present Load` 下的力矩 |
| **5** | **静态保持** | 站立时各关节力矩 | 读 `Present Load` |
| **6** | **摩擦** | 库仑摩擦 + 粘滞 | 慢速匀速运动，看力矩 |
| **7** | **回程间隙** | backlash | 正反向往复，看位置滞回 |
| **8** | **总质量与质心** | 验证 CAD 值 | 称重 + 悬挂法 |

**⚠️ 舵机支持读回 `Present Position` / `Present Load` / `Present Speed` / `Present Voltage` / `Present Temperature` —— 够做 1~7 项。**

### 5.2 前置条件

**做系统辨识需要固件的"手动调试模式"：**

```
上位机发命令 → 固件直接驱动单个关节做指定动作
并回传：位置 / 力矩 / 速度 / 电压 / 温度
```

**⚠️ 这个功能要在写固件时就设计进去，不要等到要用时再加。**

### 5.3 迭代流程

```
① 测出 PD 增益、延迟、摩擦
② 填回仿真
③ 重新训练（或微调）
④ 再上真机
⑤ 重复 2~3 轮
```

**⚠️ 迭代 2~3 轮是正常的，不是失败。**
