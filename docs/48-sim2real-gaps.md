## G1 · 关节限位不一致 🔴 阻塞

### 证据 1：两个 URDF 的 thigh 上限差 3 倍

| 关节 | 实机 `hardware/mechanical/URDF/robot.urdf` | 仿真 `Sim/legged_gym/resources/robots/rlcat/urdf/robot_sim.urdf` |
|---|---|---|
| hip | [0°, 40°] | [0°, 40°] ✅ |
| **thigh** | **[−35°, +30°]** | **[−35°, +90°]** ⚠️ |
| calf | [−60°, +60°] | [−60°, +60°] ✅ |

**⚠️ 仿真 URDF 带 `_sim` 后缀，说明是**有意修改**过的。但实机只有 30°。**

### 证据 2：仿真配置把限位彻底关掉了

```python
# Sim/legged_gym/legged_gym/envs/rlcat/rlcat_config.py
class asset(LeggedRobotCfg.asset):
    dof_pos_limits = -10.0          # ⇒ 实际限位 [−10, +10] rad = ±573°，等于不限
```

### 证据 3：用实机限位衡量 1000 步仿真回放

```
q_target 越界的时间步:  956 / 1000 =  95.6%
q(实测)  越界的时间步:  992 / 1000 =  99.2%      ← ⚠️ 几乎全程
```

**逐关节（实测 `q` 越界占比）：**

| 关节 | 越界占比 | 仿真实测范围 | 实机允许 |
|---|---|---|---|
| **rf_hip** | **97.6%** | [−36.2°, +9.2°] | [0°, 40°] |
| lb_hip | 9.6% | [−8.3°, +46.9°] | [0°, 40°] |
| rf_thigh | 6.2% | [−1.7°, +35.4°] | [−35°, 30°] |

### 两种解释，必须先分清

| 解释 | 判据 | 处理 |
|---|---|---|
| **A. 仿真真的不限位** | 实机上 `rf_hip` **不能**转到负角 | 🔴 **必须重训**（仿真用实机限位 + 限位惩罚） |
| **B. 某条腿 hip 轴向符号相反** | 实机上 `rf_hip` **能**转到负角（镜像） | 🟡 只需对齐符号，不用重训 |

**⚠️ 请你用实机验证：把 `rf_hip` 手动往两个方向推，看它能不能过 0°。**
**（或者看标定时的 `dir`：如果 `rf_hip` 的 dir 与其他 hip 不同，就是 B。）**

### 如果确认是 A（不限位）的最小修法

1. **删掉 `dof_pos_limits = -10.0`**，让 URDF 限位生效
2. **仿真 URDF 的 thigh 上限改回 30°**（与实机一致）
3. **加限位惩罚**（`dof_pos_limits` 惩罚项），让策略学会不撞限位
4. **重训**

**⚠️ 这是"训练配置错误"，不是策略本身不行 —— 重训后大概率能恢复。**

### 短期：如果不重训就想试

**`rl_policy.action_to_q_target()` 默认会夹软限位。** 实测：

```
裁剪后的目标偏差: max 62.3°   平均 2.1°
平均每步被裁的关节数: 1.0 个 / 12
```

**⇒ 平均只裁 1 个关节、2.1°，**大部分时间影响不大**；但 `rf_hip` 那条会系统性失效。**

**⚠️ 所以：可以试，但**不要期待它能像仿真里那样走**。**主要用于验证"能不能站"。**

## G2 · 仿真没有驱动器延迟 🔴 阻塞

**仿真里的舵机是"理想伺服"** —— 给了目标角度，**下一个物理步就到位**，延迟 ≈ 0。

**真机：**

```
总线 SyncWrite            ~1 ms
舵机内部 PID 响应          ?
────────────────────────────────
总延迟 1~3 个控制周期 = 10 ~ 30 ms
```

**⚠️ 在 100 Hz 回路里，10~30 ms = 1~3 个周期的**纯延迟**，闭环相位裕度直接被吃掉。**

| 现象 | 原因 |
|---|---|
| 真机震荡，仿真看不出来 | 延迟在仿真里不存在 |
| 吊起时看不出来，落地才暴露 | 吊起不承重，关节不受外力 |

### 修法

| 方案 | 成本 | 效果 |
|---|---|---|
| **① 真机降速跑**（action ×0.5 或降策略频率） | 免费 | 立刻减小相对影响 |
| **② 仿真加"动作延迟队列" + 域随机化**（每次 reset 随机 1~3 步） | 中 | ⭐ 根治 |
| ③ 提高舵机内部 PID 刚度 | 低 | 不解决延迟 |

**⇒ 建议 ①②都做；先用①上真机验证"能站"。**

## G3 · 伺服 PD ≠ 仿真 PD 🟡

| 仿真 | 真机 |
|---|---|
| PD 控制器：`stiffness=20`、`damping=0.5`，**输出力矩** | **舵机内部 PID**，收位置指令，增益不可精确对齐 |
| 无摩擦、无齿隙、无回差 | 有摩擦、有齿隙、连杆有柔性 |

**⇒ 无法完全对齐，只能靠域随机化 + 低速起步吃掉差异。**

## G4 · `config.py` 的 thigh 上限与实机不符 🟡

```python
# pi/config.py
Q_MAX = [40, 40, 40, 40,   90, 90, 90, 90,   60, 60, 60, 60]     # thigh = 90°
```

**⚠️ 实机 URDF 是 30°。`config.py` 跟着**仿真**写成了 90°。**

**⇒ 如果确认实机是 30°，`Q_MAX` 的 thigh 应改成 30°**（`Q_SOFT_MAX` 会自动跟着算）。

**⚠️ 但改了之后，`rl_policy` 的裁剪会更严格 —— 这正是 G1 的后果。所以 G1 和 G4 要一起处理。**
