## 1. 项目概述

**RL-CAT** 是一只 12 自由度四足机器人：

```
形态：四足，每腿 3 关节（髋外摆 + 髋俯仰 + 膝）
尺寸：机身 200 × 72 × 58 mm，站立高度 216 mm
重量：CAD 计 1.386 kg（含 12 个舵机、Pi 5、电池、PCB）
算力：树莓派 5 (4GB) 跑策略，STM32F103C8 做下位机
执行：12 个 Feetech ST-3215-C018 总线舵机
目标：强化学习训练 → sim-to-real 部署
```

**整体技术路线：**

```
SolidWorks 建模 → URDF → Isaac Gym 仿真 → PPO 训练 → 域随机化
                                                          ↓
真机部署 ← 系统辨识 ← 仿真验证 ←───────────────────────────┘
```

### 2.2 控制系统架构

```
┌──────────────┐  UART 1 Mbps   ┌──────────────┐  总线 1 Mbps  ┌─────────┐
│ Raspberry Pi 5│ ─────────────→ │ STM32F103C8  │ ────────────→ │ 12 舵机 │
│  (策略推理)   │ ←───────────── │  (100 Hz 控制)│ ←──────────── │         │
└──────────────┘                └──────────────┘               └─────────┘
                                        │
                                        │ 软件 I2C (PB8/PB9)
                                        ↓
                                   JY901P IMU
                                   (内部融合，输出姿态)
```

| 参数 | 值 |
|---|---|
| **控制频率** | **100 Hz** |
| 通信方式 | USART1 → Pi (1 Mbps)、USART2 → 舵机 (1 Mbps)、USART3 → ESP32-C3 (921600) |
| IMU | JY901P，**内部做姿态融合**，MCU 只需读结果 |
| ⚠️ IMU 波特率 | 必须设成 921600（默认 115200 会占 19% CPU） |

**时序预算（1 Mbps，12 舵机）：**

```

syncRead 回读： 1.53 ms
合计 2.55 ms = 100 Hz 周期的 26%    ← 可接受
```

### 2.4 关节定义

**腿编号：lf = 左前、lb = 左后、rf = 右前、rb = 右后。**

**⚠️ 三套"顺序"是不同的，不要混淆：**

| 顺序体系 | 排列方式 | 用途 |
|---|---|---|
| **A. 固件/训练索引** | **按关节类型分组**（0–3 外摆、4–7 髋俯仰、8–11 膝） | 观测/动作向量、固件数组 |
| **B. URDF 声明顺序** | **按腿分组**（lf_hip, lf_thigh, lf_calf, lb_hip, …） | URDF 文件里的书写顺序 |
| **C. Isaac Gym DOF 顺序** | 待实测，可能等于 B，也可能重排 | `get_asset_dof_names()` 的返回顺序 |

**👉 推荐做法：以 A 为"逻辑索引"，把 B/C 都视为物理顺序，在代码里做映射。**

#### A. 固件/训练索引（推荐作为逻辑索引）

```
0–3   髋外摆 (abduction)：lf_hip, lb_hip, rf_hip, rb_hip
4–7   髋俯仰 (hip pitch)：lf_thigh, lb_thigh, rf_thigh, rb_thigh
8–11  膝     (knee)     ：lf_calf, lb_calf, rf_calf, rb_calf
```

#### B. URDF 声明顺序（实测，共 12 个）

```
索引: 0        1         2         3        4          5         6
名字: lf_hip   lf_thigh  lf_calf   lb_hip   lb_thigh   lb_calf   rf_hip

索引: 7         8         9        10        11
名字: rf_thigh  rf_calf   rb_hip   rb_thigh  rb_calf
```

**即"按腿分组"（lf → lb → rf → rb，每条腿内 hip → thigh → calf），与 A 的"按类型分组"完全不同。**

#### ⚠️ 映射表（A ↔ B）

**从逻辑索引 A 到 URDF/物理索引 B：**

```python
# A 索引 -> URDF 名
A_to_name = [
    "lf_hip", "lb_hip", "rf_hip", "rb_hip",           # 0-3  外摆
    "lf_thigh", "lb_thigh", "rf_thigh", "rb_thigh",   # 4-7  髋俯仰
    "lf_calf", "lb_calf", "rf_calf", "rb_calf",       # 8-11 膝
]

# URDF 声明顺序（B）
B_names = [
    "lf_hip", "lf_thigh", "lf_calf",
    "lb_hip", "lb_thigh", "lb_calf",
    "rf_hip", "rf_thigh", "rf_calf",
    "rb_hip", "rb_thigh", "rb_calf",
]

# 建立映射：A 索引 -> B 索引
A2B = [B_names.index(n) for n in A_to_name]
# 实测结果（Isaac Gym 若与 URDF 声明顺序一致）：
# A2B = [0, 3, 6, 9, 1, 4, 7, 10, 2, 5, 8, 11]
```

**⚠️ 如果 Isaac Gym 的 DOF 顺序不等于 B，先做 B→C 的映射，再套 A2B。**

**机身坐标系：X 向前、Y 向左、Z 向上，原点 = 机身中段中心的地面投影。**

| **站立膝夹角** | **122.4°**（大腿与小腿之间的夹角，此时腿是弯的） |
| 大腿与垂直夹角 | 34.03° |
| 小腿与垂直夹角 | 23.6° |
| 膝力矩臂 | 42.0 mm |
| 站立时膝力矩 | 0.432 N·m（@1.386 kg 总重，动态系数 2.5） |
| **膝可动范围** | **距完全伸直 0° ~ 120°** ⚠️ 见下方说明 |
| 髋外摆范围 | 0° – +30°（**不对称，不做内摆**） |
| 髋间距 | **横向 ±55 mm；纵向 ±100 mm**（前轴到后轴 200 mm） |
| 机身 | 200 × 72 × 58 mm |
| 足端 | 球形橡胶，半径 9 mm |

### 3.2 ⚠️ 关于"膝角"的两个不同参考（极易混淆）

**必须区分这两个角，它们的参考系不同：**

| 名称 | 参考 | 站立时的值 | 说明 |
|---|---|---|---|
| **膝夹角** | 大腿与小腿之间的夹角 | **122.4°** | 180° = 完全伸直 |
| **膝屈曲量** | 距完全伸直的旋转量 | **57.6°** | = 180° − 122.4° |

**所以"膝活动范围 60°–150°"这个说法本身是矛盾的：**

```
如果它指【膝屈曲量】：站立需要 57.6°，而 60° 下限 > 57.6° → 站立姿态【够不到】
如果它指【膝夹角】  ：站立 122.4° 落在 60–150 内 ✅，但 150° 意味着腿比站立还弯
```

**👉 结论：设计文档里那个"60°–150°"的取值范围定义不清晰，必须以仿真实测为准（见 §6.4）。**

**可用的物理约束（更可靠）：**

| 约束 | 值 | 来源 |
|---|---|---|
| 膝最大屈曲 | 腿最短时 ≈ 60° 膝夹角（深蹲） | 设计目标 |
| 膝完全伸直 | 180° 膝夹角（= 屈曲 0°，机械上可能顶死） | 机构 |
| **站立** | **122.4° 膝夹角** | 必须可达 |

### 3.3 ⚠️ 设计目标值 vs URDF 实测值（对不上，以 URDF 为准）

**从 URDF 的 joint `<origin>` 反推出的实际连杆长度：**

| 量 | 设计值 | **URDF 实测** | 说明 |
|---|---|---|---|
| 髋外摆轴 → 髋俯仰轴 | ~20 mm（外摆臂） | **64.96 ~ 71.07 mm** | ⚠️ 这段含的外摆臂 + 髋部结构，不等于纯外摆臂长 |
| **髋俯仰轴 → 膝轴** | 大腿 75 mm | **63.61 ~ 64.96 mm** | 偏短约 10~15% |
| **膝轴 → 踝/足端** | 小腿 105 mm | **75.78 mm** | ⚠️ 偏短约 28% |

**⚠️ 这个偏差说明：**

```
① 设计文档里的 75/105 是"连杆的物理长度"（零件外形尺寸）
② URDF origin 长度是"关节轴心之间的距离"
③ 两者不等，因为轴心不在零件端点（舵机输出轴有偏心、踝部有偏置）
```

**👉 计算站立姿态的关节角时，必须用 URDF 的轴心距（63.61 / 75.78），不能用 75/105。**

**⚠️ 用 §3.1 的 34.03° / 57.6° 等角度值之前，要用实际轴心距重新算一遍。**

### 3.4 堵转扭矩的三个数值（都对，参考条件不同）

| 值 | 条件 | 用途 |
|---|---|---|
| **2.942 N·m** | 12 V（舵机标称电压） | 官方规格书值 |
| **2.721 N·m** | 3S 标称 11.1 V | 实际电池下的估算（电压低 → 扭矩低） |
| **3.0 N·m** | — | **URDF `effort` 设的上限，取整并留余量** |

**⚠️ URDF 的 `effort = 3.0` 略大于物理堵转扭矩，这是有意为之：** 它作为安全上限，真正的限幅由 PD 控制器和舵机自身的过流保护完成。

### 5.6 ⚠️ 运动学余量分析（新限位的关键检查）

**我用 §5.4 的轴心距（63.61 / 75.78 mm）和站立髋高 158.4 mm 反推了站立姿态，再和限位对比：**

#### 站立姿态需要的关节角（估算）

**输入（全部来自 §5.4 的实测轴心距）：**

```
大腿（髋俯仰轴 → 膝轴）  A = 63.61 mm
小腿（膝轴 → 踝轴）      B = 75.78 mm
腿总长                    L = 139.39 mm
站立髋高（h/L = 0.88）    h = 122.66 mm
```

**计算过程（已用余弦定理和正弦定理交叉验证）：**

```
① 形成三角形：A=63.61, B=75.78, 第三边 h=122.66
② 大腿与垂直夹角 α（余弦定理）:
     cos α = (A² + h² − B²) / (2·A·h) = (4046.2 + 15045.5 − 5742.6) / (2×63.61×122.66)
           = 13349.1 / 15606.5 = 0.8553
     α = 31.19°

③ 膝夹角 θ（余弦定理）:
     cos θ = (A² + B² − h²) / (2·A·B) = (4046.2 + 5742.6 − 15045.5) / (2×63.61×75.78)
           = −5256.7 / 9640.7 = −0.5453
     θ = 123.05°

④ 站立时的膝关节屈曲量（正弦定理验证一致）:
     β = arcsin(A·sin α / B) = arcsin(63.61 × 0.5179 / 75.78) = 25.76°
```

| 量 | 结果 |
|---|---|
| 大腿与垂直夹角 α | **31.19°** |
| 膝夹角 θ | **123.05°** |
| **站立时的髋俯仰关节角** | **≈ +31.19°** |
| **站立时的膝关节角** | **≈ +25.76°** |

**⚠️ 这与 §3.1 的 34.03° / 122.4° 略有差异（因为轴心距 ≠ 设计连杆长度）。以本节为准，但仿真里必须实测确认。**

#### 余量对比

| 关节 | 限位 | 站立值 | **正向余量** | **反向余量** |
|---|---|---|---|---|
| `*_hip` | 0° ~ +40° | 0° | 40.0° | 0° ⚠️ |
| `*_thigh` | −35° ~ +30° | **≈ +31.19°** | **−1.19°** ⚠️⚠️ | 66.19° |
| `*_calf` | −60° ~ +60° | **≈ +25.76°** | 34.24° | 85.76° |

#### ⚠️⚠️ 结论：**髋俯仰的 +30° 上限【不够】—— 站立姿态超出限位**

## 12. 附录：观测/动作定义（RL 接口）

### 观测（50 维，⚠️ 固件与仿真必须位对齐）

| 索引 | 内容 | 缩放 | 维度 |
|---|---|---|---|
| **0–2** | **重力向量（机身系，从四元数反算）** | 1.0 | 3 |
| **3–5** | **机身角速度（陀螺）** | ×0.25 | 3 |
| 6–8 | 速度指令 (vx, vy, ωz) | 1.0 | 3 |
| 9–20 | 关节位置 (12) | 1.0 | 12 |
| 21–32 | 关节速度 (12) | ×0.1 | 12 |
| 33–44 | 上一帧动作 (12) | **×4.0** | 12 |
| 45–46 | 步态相位 sin / cos | 1.0 | 2 |
| **47–49** | **保留 / 待定** ⚠️ | — | **3** |
| | | **合计** | **50** |

**⚠️ 勘误：** 本文档早期版本的表格漏了第 47–49 行的 3 维，导致相加只有 47 维。**50 维是设计值，那 3 维的具体用途待定**（候选：机身线速度估计、足端接触标志、上一帧力矩）。

**⚠️ 关于 ×4.0 的解释：** 动作的实际尺度是 `0.25 rad/单位`（见下），所以观测里的"上一帧动作"要做**逆缩放**——把"被缩放后的动作"还原成约 ±1 的量级，即除以 0.25 = **×4.0**。两者是配套的，不是矛盾。

**⚠️ 关于 ×0.25 / ×0.1：** 这些缩放系数是让各维度的数值量级相近，便于网络学习。**固件和仿真必须用同一套系数**，否则策略行为不一致。

**⚠️ 重力向量不要用欧拉角**（±90° 附近有奇异）。

### 动作（12 维）

```
q_target[i] = q_default[i] + 0.25 * action[i]     # rad
然后 clamp 到软限位
```

**⚠️ `action` 经过 tanh 后落在 [-1, 1]，所以单步最大改变 0.25 rad（14.3°）。**

**⚠️ 软限位 = 硬限位再内缩一点**（例如内缩 5°），防止策略把关节顶到硬限位。**具体数值待定。**

### 策略网络

```
Actor:  MLP [256, 128, 64]
Critic: MLP [256, 128, 64]
算法:   PPO
推理:   ~200 Hz（真机上），导出 ONNX
```

**⚠️ 控制频率是 100 Hz（见 §2.2）—— "200 Hz" 指策略推理能力，实际下发仍按 100 Hz 控制周期。两者不冲突。**
