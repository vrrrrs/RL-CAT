# RL-CAT 项目流程规划

> 本文档只描述**分工与流程**：每条线做什么、产出什么、线之间怎么交接、卡住了往哪回退。
> **不涉及时间安排。** 具体技术参数见 `方案.md`。
>
> **阅读方式**
> - 「→」表示依赖：前者完成后者才能开始
> - 「⇢」表示无依赖，可完全并行
> - 「↺」表示回退：出问题时回到上游哪一步

## 二、开工前提：采购与验证线

**这是所有线的前提。没有它，下面六条线只能靠猜。**

### 职责
1. 确定舵机型号与供应商，下单（含备件）
2. 采购驱动板、STM32、IMU、无线的实物
3. **做完"到货即验"清单**（见 `方案.md` §8.1）
4. 把验证结果回灌给电路线和固件线

### 产出
| 产出 | 给谁用 |
|---|---|
| 舵机实物 + 实测尺寸 | → 机械线（CAD 建模） |
| **舵机的实测时延 / 带宽 / 饱和 / 背隙** | → 仿真线（域随机化参数）、固件线（超时设置） |
| **驱动板 UART 实测耗时** | → 固件线（确定控制环频率） |
| **总线上升沿实测** | → 电路线（决定要不要加上拉） |
| 舵机内部电容容量 | → 电路线（决定要不要加去耦） |
| 波特率 / 引脚定义确认 | → 电路线（画接口）、固件线（初始化） |

### 关键原则
> **先用最小配置打样，再批量下单。**
> 2 个舵机 + 1 块驱动板就能验证技术风险最高的假设（总线通信、时延、带宽）。
> **不要在验证之前买齐 12 个。**

### 回退
```
↺ 如果驱动板 UART 实测耗时远超预期
     → 回到"电路线"，重新评估是否需要 2 块驱动板
↺ 如果总线在 1 Mbps 下误码率高
     → 回到"固件线"，把波特率降到 500k / 250k 重新标定控制环频率
```

## 三、线②：机械设计

### 阶段流程（严格按序，不要跳）

```
②-1 参数表冻结
      ↓  依据：方案.md §1 的尺寸表 + 采购线的实测舵机尺寸
②-2 单腿建模（一条腿的完整装配）
      ↓
②-3 干涉检查（外摆 ±25°、膝 60~150° 全行程扫一遍）
      ↓
②-4 机身建模（内腔布局：Pi / 电池 / PCB / 散热）
      ↓
②-5 配平重心（移到支撑多边形中心附近）
      ↓
②-6 出打印件 + 装配验证（第一台样机）
      ↓
②-7 🚩 样机 v1 冻结
      ↓
②-8（推迟）外观优化 / 减重 / 走线整理
```

### 每阶段的验收标准

| 阶段 | 验收标准 | 不通过怎么办 |
|---|---|---|
| ②-1 | 尺寸表里所有数字都有来源（实测 / 推导） | 回采购线补测 |
| ②-2 | 单腿能装配、无穿模 | 改支架 |
| ②-3 | **全行程无干涉**（这是最容易翻车的一步） | 改外摆臂长度或机身宽度 |
| ②-4 | **Pi 5、电池盒、PCB 都能物理放进去** | 回 ②-1 重新分配尺寸 |
| ②-5 | 重心投影落在支撑多边形内 | 调整器件位置 |
| ②-6 | 能用手转动全部 12 个关节，无卡涩 | 修打印件 |
| ②-7 | **此后不再改结构** | — |

### 最关键的两个决策点

> **②-3 和 ②-4 是机械线的两个"悬崖"。**
> - ②-3 失败 = 腿的尺寸要改 → 扭矩预算要重算 → 可能影响舵机选型
> - ②-4 失败 = 机身尺寸要改 → 内腔布局重做 → 可能影响 PCB 尺寸
>
> **这两个阶段要多花时间反复试，不要急着往下走。** 它们的成本远低于"打印出来才发现装不上"。

### 产出
| 产出 | 给谁用 |
|---|---|
| CAD 装配体 + 工程图 | → 打印 / 加工 |
| **打印件 STEP/STL** | → 装配线 |
| **关节轴心坐标表** | → 仿真线（URDF）、固件线（运动学） |
| **关节活动范围表** | → 固件线（软限位）、仿真线（joint limit） |
| **实物尺寸与重量** | → 仿真线（惯性参数） |

### 回退
```
↺ ②-6 装配发现卡涩/干涉 → 回 ②-2 或 ②-3
↺ ②-4 发现器件放不下  → 回 ②-1 重新分配尺寸
↺ ②-5 重心偏高        → 回 ②-4 调整器件布局
```

## 四、线③：电路设计

### 阶段流程

```
③-1 接口定义（把所有连接器、引脚、电压列成一张表）
      ↓  依据：方案.md §4、§5
③-2 原理图设计（功率区 + 逻辑区）
      ↓
③-3 评审（重点：接地分区、大电流路径、信号完整性）
      ↓
③-4 PCB 布局布线
      ↓  重点：功率区铺铜、电容贴负载、地分区、信号远离功率
③-5 出 Gerber → 打样（含 SMT）
      ↓
③-6 上电验证（先不接舵机和 Pi，只验电源）
      ↓
③-7 分模块联调（先驱动板，再 IMU，再无线，最后 Pi）
      ↓
③-8 🚩 电路冻结
```

### 每阶段的验收标准

| 阶段 | 验收标准 |
|---|---|
| ③-1 | 每个连接器的**引脚号、线序、电压**都写明；无"待定"项 |
| ③-2 | 功率区和逻辑区在原理图上已经**物理分开** |
| ③-3 | **接地策略有人复核过**（这是最容易出错的地方） |
| ③-4 | 大电流路径是**铺铜不是走线**；每个电容紧贴负载；过孔数量够 |
| ③-6 | 各路电压正确、无短路、无异常发热 |
| ③-7 | 每个模块单独能通 |

### ⚠️ 三个必须提前定的东西

| # | 项目 | 为什么必须在画板前定 |
|---|---|---|
| 1 | **单片机方案**（复用 F103C8 / 换 F405 / 自制最小系统） | 决定 PCB 面积和引脚分配 |
| 2 | **Pi 5 的 5 V 供电形式**（板上降压 / 板外 UBEC） | 决定是否有 5 V 大电流区和散热设计 |
| 3 | **无线模块的具体型号与封装** | 决定接口和独立的 3.3 V 供电能力 |

### 上电验证的五个步骤（严格按序，不要跳）

```
③-6a 只焊电源部分，不焊 MCU 和其他模块
      → 验各路电压、纹波、发热
      ↓
③-6b 焊 MCU，只跑点灯 / 串口打印
      → 验最小系统
      ↓
③-6c 接驱动板（不接舵机），发 Ping
      → 验 UART 接线和电平
      ↓
③-6d 接 1 个舵机，做位置读写
      → 验总线 + 舵机
      ↓
③-6e 接 IMU + 无线，逐个验
      ↓
③-7 接满 12 舵机 + Pi，做整机联调
```

> **③-6c 和 ③-6d 之间不要跳。** 接满 12 舵机再发现接线错误，排查成本是接 1 个时的十倍。

### 产出
| 产出 | 给谁用 |
|---|---|
| **接口定义表**（连接器/引脚/电压） | → 固件线、装配线 |
| Gerber + BOM | → 打样 |
| **上电验证记录** | → 装配线（接线依据） |

### 回退
```
↺ ③-6 电压异常        → 回 ③-4 改布局
↺ ③-7 某模块不通      → 回 ③-2 查原理图
↺ ③-7 通信偶发错误    → 回 ③-4 查地分区和信号走线
```

## 五、线④：下位机固件

### 阶段流程

```
④-1 库移植（把官方 F103 库搬进来，替换 UART 层）
      ↓  依据：方案.md §6.1 / §6.5
④-2 单舵机通信打通（Ping + 读写位置）
      ↓
④-3 多舵机通信（SyncWrite 下发 + 批量回读）
      ↓
④-4 控制环骨架（定时器中断 + 分层：传感器层/控制层/通信层）
      ↓
④-5 IMU 接入（软件 I2C + 解析 + 姿态读取）
      ↓
④-6 与树莓派的协议（定长二进制帧 + CRC + 序号 + 时间戳）
      ↓
④-7 安全层（整帧超时 / 限幅 / 心跳 / 失联急停）
      ↓
④-8 系统辨识固件（阶跃 / 扫频测试模式）
      ↓
④-9 上位机联调（配合线⑧）
      ↓
④-10 🚩 固件冻结
```

### 每阶段的验收标准

| 阶段 | 验收标准 |
|---|---|
| ④-1 | 库能编译通过；能 Ping 到一个舵机 |
| ④-2 | 能读回位置、速度、负载、电压、温度、电流 |
| ④-3 | 12 舵机 SyncWrite 一轮；批量回读一轮；记录耗时 |
| ④-4 | **控制环周期稳定不丢帧**（用示波器翻转 IO 测抖动） |
| ④-5 | IMU 数据能读到，方向正确 |
| ④-6 | Pi 侧能收到完整观测帧，丢包率 <1e-4 |
| ④-7 | **拔掉 Pi 的线，机器人能安全停止** |
| ④-8 | 能按命令做阶跃/扫频，并输出原始数据 |

### ④-8 是整条线里最容易被跳过、但最重要的一步

> **系统辨识固件不是一个"附加功能"，它是 sim-to-real 的输入。**
> 没有它，仿真里的舵机模型只能是猜的，策略迁移必然失败。
>
> **要测的量：**
> - 每个关节的**阶跃响应**（指令 → 实际位置的上升时间、超调、稳态误差）
> - 每个关节的**带宽**（扫频）
> - **饱和特性**（不同负载下的最大速度）
> - **背隙**（正反转的换向死区）
> - **纯延迟**（从发指令到位置开始变化的时间）

### 产出
| 产出 | 给谁用 |
|---|---|
| 固件源码 + 烧录文件 | → 装配线 |
| **系统辨识原始数据**（每关节的时延/带宽/饱和/背隙） | → **仿真线（域随机化参数，最关键）** |
| 通信协议定义 | → 上位机线 |
| 控制环实际周期与抖动数据 | → 仿真线（时延建模） |

### 回退
```
↺ ④-3 通信不稳        → 回"采购线"重测物理层；或降波特率
↺ ④-4 控制环丢帧      → 回 ④-3 检查总线耗时是否超预算
↺ ④-7 急停不可靠      → 回 ④-4 检查安全层是否在正确的中断优先级
↺ ④-8 测不出干净的阶跃响应 → 回 ②-6 检查机械是否有卡涩/背隙过大
```

## 六、线⑤：仿真与训练

**这条线可以最早开始，也可以最独立。**

### 阶段流程

```
⑤-1 仿真环境搭建（装 MuJoCo 或 Isaac Lab，跑通官方四足示例）
      ↓
⑤-2 用"占位参数"搭 12 DOF 模型
      → 此时用估计值，不等辨识结果
      ↓
⑤-3 观测 / 动作空间定义（与固件侧共用一份定义）
      ↓
⑤-4 奖励函数 v0（站立 + 速度跟踪）
      ↓
⑤-5 手写 PD 让模型站着（先不用 RL，验证模型合理）
      ↓
⑤-6 域随机化框架（质量 / 摩擦 / 时延 / 噪声 的随机化槽位）
      ↓
⑤-7 PPO 训练站立 → 速度跟踪
      ↓
⑤-8 ⚠️ 用④-8的实测参数替换估计值，重训
      ↓
⑤-9 导出策略（ONNX）→ 交给上位机线
      ↓
⑤-10（循环）根据真机表现调整随机化范围，重训
```

### 关键设计约束

| 约束 | 说明 |
|---|---|
| **⑤-3 必须与固件侧共用一份定义** | 观测/动作的维度、顺序、单位、归一化方式必须逐位对齐。**建议写成共享配置文件或代码生成**，两边都读同一份 |
| **⑤-6 的随机化范围要包含真实值** | 域随机化的区间必须覆盖实测值，否则策略在真机上会跑出训练分布 |
| **⑤-8 不是可选步骤** | 用估计参数训出来的策略，迁移到真机大概率失败 |

### ⑤-10 是这条线的常态

> **仿真线不是"训一次就结束"，而是"训 → 上真机 → 看失败模式 → 调随机化 → 再训"的循环。**
> **这个循环会占掉全项目最多的时间**，要对此有预期。

### 产出
| 产出 | 给谁用 |
|---|---|
| MuJoCo / Isaac 模型文件 | — |
| **观测/动作定义文件（共享）** | → 固件线、上位机线 |
| **训练好的策略（ONNX）** | → 上位机线 |
| 域随机化参数表 | → 上位机线（用于时延补偿） |

### 回退
```
↺ ⑤-5 模型站不住     → 回 ⑤-2 检查惯性参数和关节限位
↺ ⑤-7 训练不收敛     → 回 ⑤-4 改奖励函数
↺ 迁移到真机就摔     → 回 ⑤-6 扩大随机化范围，重点加"时延"
↺ 真机抖动异常       → 回 ④-8 补测该关节的背隙/摩擦
```

## 七、线⑥：装配与标定

### 阶段流程

```
⑥-1 机械装配（按 CAD 装配体）
      ↓
⑥-2 电气装配（按接口定义表接线）
      ↓
⑥-3 上电自检（不装腿，只验电）
      ↓
⑥-4 单关节标定（逐个关节：零位 / 方向 / 软限位）
      ↓
⑥-5 全关节联动测试（用上位机拖动滑块）
      ↓
⑥-6 整机配平（加/移配重，让重心到位）
      ↓
⑥-7 机械紧固复检（跑一段时间后重紧螺丝）
      ↓
⑥-8 🚩 机器人可交付给测试
```

### 每阶段的验收标准

| 阶段 | 验收标准 |
|---|---|
| ⑥-1 | 12 个关节都能用手自由转动，无卡涩 |
| ⑥-2 | 接线与接口定义表**逐根核对**（不要凭记忆） |
| ⑥-3 | 各路电压正确，无异常发热，无短路 |
| ⑥-4 | **每个关节的零位写进配置，方向正确，软限位能挡住** |
| ⑥-5 | 12 关节能同步平滑跟随 |
| ⑥-6 | 重心投影在支撑多边形内 |
| ⑥-7 | **跑 30 分钟后复紧所有螺丝**（3D 打印件会蠕变） |

### ⑥-4 单关节标定的标准动作

```
对每一个关节：
  1. 用软限位限制在安全范围内
  2. 手动把关节推到机械零位，读出编码器值 → 记为偏移量
  3. 发"正方向"指令，确认实际转动方向 → 记录方向符号
  4. 从最小到最大扫一遍，确认无干涉 → 记录软限位上下限
  5. 把偏移量/方向/限位写进配置文件
  6. 复测一次：发 0° 和 90°，用角度尺核对
```

> **不要一次标定 12 个再一起测。** 标一个、验一个，出问题容易定位。

### 产出
| 产出 | 给谁用 |
|---|---|
| **标定配置文件**（零位/方向/限位） | → 固件线（烧进 Flash）、仿真线（joint origin） |
| 实测总重与重心 | → 仿真线（惯性参数） |
| 装配问题清单 | → 机械线（下一版改进） |

### 回退
```
↺ ⑥-3 短路/发热     → 回"电路线"查原理图和焊接
↺ ⑥-4 某关节标不准  → 回"机械线"检查该关节的背隙/干涉
↺ ⑥-5 联动时抖     → 回"固件线"检查控制环；或回 ⑥-4 检查限位
↺ ⑥-7 螺丝松动     → 回"机械线"加大壁厚或改结构
```

## 八、线⑦：系统辨识与建模

**这是连接"仿真"和"真机"的桥梁。它同时是固件线的下游和仿真线的上游。**

### 阶段流程

```
⑦-1 设计辨识实验（测什么、怎么测、记录什么）
      ↓  输入：④-8 的辨识固件
⑦-2 逐关节做阶跃测试 → 记录指令与实际位置
      ↓
⑦-3 逐关节做扫频测试 → 记录幅频/相频
      ↓
⑦-4 测背隙（正反转换向死区）
      ↓
⑦-5 拟合参数（一阶/二阶 + 纯延迟 + 饱和）
      ↓
⑦-6 把实测延迟/带宽/饱和/背隙写进仿真参数文件
      ↓
⑦-7 在仿真里复现真机的阶跃响应（对不上就回 ⑦-5）
      ↓
⑦-8 🚩 输出参数表给仿真线
```

### 每阶段的验收标准

| 阶段 | 验收标准 |
|---|---|
| ⑦-2 | 每个关节都有干净的阶跃曲线（采样率足够，无噪声淹没有用信号） |
| ⑦-5 | **拟合模型能预测没参与拟合的另一条阶跃曲线**（交叉验证） |
| ⑦-7 | 仿真里的阶跃响应与真机**形状相似、时间尺度接近** |

### ⚠️ 这一步的常见错误

| 错误 | 后果 |
|---|---|
| 只测一个关节，假设 12 个一样 | 装配公差导致每个关节不一样，策略会在特定关节上失败 |
| 只测空载 | 带载特性和空载差很多 |
| 不做交叉验证 | 过拟合的模型在仿真里"看起来对"，迁移时才发现不对 |
| 忘测**背隙** | 背隙会让策略在换向时出现"死区"，是 RL 抖动的常见原因 |
| 忘测**纯延迟** | 时延是 sim-to-real 最大的坑，必须在训练时显式建模 |

### 产出
| 产出 | 给谁用 |
|---|---|
| **驱动器参数表**（每关节的延迟/带宽/饱和/背隙） | → **仿真线（最关键输入）** |
| 辨识原始数据 | 存档（以后重训时要回看） |

### 回退
```
↺ ⑦-2 阶跃曲线脏        → 回"固件线"改采样方式；或回"装配线"检查机械
↺ ⑦-5 拟合不上          → 回 ⑦-1 重新设计实验（可能需要更大激励）
↺ ⑦-7 仿真复现不了      → 回 ⑦-5 换模型结构（一阶→二阶）
```

## 九、线⑧：上位机软件

### 阶段流程

```
⑧-1 通信层（与 STM32 的二进制协议，独立线程 + 无锁缓冲）
      ↓
⑧-2 遥测与可视化（实时曲线 + 状态面板）
      ↓
⑧-3 遥控输入（手柄 / 键盘 / 无线）
      ↓
⑧-4 日志系统（二进制日志落盘 + 回放工具）
      ↓
⑧-5 推理引擎（ONNX Runtime，独立高优先级线程）
      ↓
⑧-6 实时性调优（SCHED_FIFO + CPU 隔离 + 端到端延迟测量）
      ↓
⑧-7 策略部署（加载 ONNX，闭环运行）
      ↓
⑧-8 🚩 上位机可用
```

### 关键设计约束

| 约束 | 说明 |
|---|---|
| **不要用 ROS 2 进控制环** | DDS 抖动大。ROS 2 只用于日志/可视化/遥控（如果需要的话，甚至可以不用） |
| **推理线程与通信线程分离** | 用无锁 SPSC 环形缓冲，不要共享锁 |
| **必须记录真实时间戳** | 策略要知道 `dt` 不是恒定的。这是 sim-to-real 的标准做法 |
| **日志必须能回放** | 复盘真机失败时，回放比重新跑一遍便宜得多 |

### 产出
| 产出 | 给谁用 |
|---|---|
| 上位机程序 | → 测试 |
| **遥测可视化工具** | → 装配线（标定）、辨识线（看曲线） |
| **日志回放工具** | → 整个 sim-to-real 阶段 |

### 回退
```
↺ 端到端延迟过大   → 回 ⑧-6 调优；或回"固件线"减少每周期数据量
↺ 推理线程被抢占   → 回 ⑧-6 检查 CPU 隔离和线程优先级
```

## 十、汇聚点：SIM-TO-REAL 迭代

**这是全项目最耗时、最需要耐心的环节。它是⑦和⑤的联合循环。**

```
      ┌──────────────────────────────────────────┐
      │                                          │
      ↓                                          │
  训练策略（⑤）                                   │
      ↓                                          │
  部署到真机（⑧）                                 │
      ↓                                          │
  ┌───────────────────┐                          │
  │ 真机测试           │                          │
  │ · 先吊起来测       │                          │
  │ · 再落地站立       │                          │
  │ · 再慢速前进       │                          │
  │ · 再全向           │                          │
  └─────────┬─────────┘                          │
            ↓                                    │
      ┌───────────┐                              │
      │ 失败模式   │                              │
      │  分类      │                              │
      └─────┬─────┘                              │
            │                                    │
   ┌────────┼────────┬────────────┐              │
   ↓        ↓        ↓            ↓              │
 抖/振荡  走偏    摔倒/软    不响应              │
   │        │        │            │              │
   ↓        ↓        ↓            ↓              │
回⑦测    回⑤调    回⑤扩大    回④/③查           │
背隙/摩擦 奖励函数  随机化     通信/硬件          │
   │        │        │            │              │
   └────────┴────────┴────────────┘              │
                    │                            │
                    └────────────────────────────┘
```

### 安全测试顺序（不可颠倒）

| 步骤 | 做法 | 通过标准 |
|---|---|---|
| 1 | **吊起来**（腿悬空） | 关节按预期动作，无异常发热 |
| 2 | **落地站立**（手扶着） | 能保持站姿，不剧烈抖 |
| 3 | **放开站立** | 自主站稳 30 秒 |
| 4 | **慢速前进** | 能直走 1 米不摔 |
| 5 | **转向** | 能原地转 90° |
| 6 | **全向 + 加速** | 达到目标速度 |

> **每一步都要有物理急停开关在手边。**
> **不要因为"上次没事"就跳过某一步。**

### 失败模式速查表

| 现象 | 最可能的原因 | 往哪回退 |
|---|---|---|
| 关节高频抖动 | 背隙 / 摩擦建模不准 | ⑦ 补测背隙 |
| 整体低频振荡 | 时延没建模 / 增益过高 | ⑤ 加时延随机化 |
| 站立慢慢下沉 | 扭矩不足 / 模型质量偏轻 | ② 减重 或 ⑦ 校正质量 |
| 走偏不直 | 关节零位标定误差 | ⑥ 重新标定 |
| 某一关节特别差 | 该关节机械问题 | ⑥→② 检查机械 |
| 真机完全不动 | 通信 / 使能 / 急停 | ④→③ 查链路 |
| 学得会但迁移失败 | 观测分布不匹配 | ⑤ 检查定义是否逐位对齐 |
| 电池一用就复位 | 5 V 供电被舵机拉崩 | ③ 查供电与接地 |

## 十二、贯穿全项目的七条原则

| # | 原则 | 说明 |
|---|---|---|
| **1** | **机械要早冻结** | 改结构 = 标定全废 = 策略重训。外观优化推迟到最后 |
| **2** | **系统辨识不能省** | 它是 sim-to-real 的分水岭，不是可选项 |
| **3** | **定义要共享** | 观测/动作定义、关节限位、零位必须仿真和真机读**同一份** |
| **4** | **单步验证，不要跳** | 上电、标定、测试都按顺序，每一步单独通过再往下 |
| **5** | **安全层优先于功能** | 急停、限幅、心跳要在做功能之前就位 |
| **6** | **数据驱动决策** | 不确定的事（IMU 延迟、总线速率、舵机上拉）先测再定，不要拍脑袋 |
| **7** | **一次只改一个变量** | sim-to-real 阶段尤其重要，否则永远不知道是哪个改动起作用 |

## 十四、最容易出问题的六个地方

| # | 风险点 | 预防措施 |
|---|---|---|
| **1** | **②-3 干涉检查没做全** | 外摆和膝的**全行程**都要扫，不能只看站立姿态 |
| **2** | **③ 接地没分区** | 24 A 回流会让 IMU 数据变脏、总线偶发错误。**这是最难定位的故障** |
| **3** | **④-8 系统辨识被跳过** | 直接导致 sim-to-real 失败，而且失败时你会怀疑错方向 |
| **4** | **⑤-3 观测定义两边不一致** | 仿真和真机的维度/顺序/单位差一点，策略就完全失效 |
| **5** | **⑥-4 标定没逐个验** | 一次标 12 个再一起测，出问题无法定位是哪个 |
| **6** | **⑨ 测试跳步骤** | 不吊起来直接落地，第一台样机大概率会摔坏 |
