## 1. 机械尺寸与关节距离

### 1.1 坐标约定

```
机身坐标系（世界坐标，单位 mm）
  原点 = 机身中段中心在地面上的投影
  X 轴 = 向前（机头方向）
  Y 轴 = 向左
  Z 轴 = 向上（地面 = 0）

腿的横向位置：左前 LF / 左后 LH 在 y > 0；右前 RF / 右后 RH 在 y < 0
```

### 1.2 关节轴定义

| 关节 | 转轴方向 | 功能 |
|---|---|---|
| **髋外摆** Hip Abduction | **沿 X（前后）** | 腿在额状面内外摆 |
| **髋俯仰** Hip Pitch | **沿 Y（左右）** | 腿在矢状面前后摆 |
| **膝** Knee | **沿 Y（左右）** | 小腿前后摆 |

> ⚠️ 这是本节最容易搞错的地方。外摆轴是**前后方向**，所以外摆舵机的输出轴指向前后，其 40.2 mm 的机体长度落在**机身长度方向**上，不是宽度方向。

### 3.2 为什么选 C018（同系列三款的对比）

| 型号 | 额定电压 | 堵转扭矩 | 空载转速 | 堵转电流 | 齿轮 | 能否上 3S |
|---|---|---|---|---|---|---|
| **ST-3215-C018** | **12 V（6~14V）** | **30 kg·cm @12V** | 45 RPM | 2.7 A | 铜 | ✅ **可以** |
| STS3215-C001 | 7.4 V（4~7.4V） | 19.5 kg·cm @7.4V | 52 RPM | 2.5 A | 铜 | ❌ 12.6V 超上限 |
| ST-3215-C044 | 7.4 V（5~8.4V） | 16.0 kg·cm @7.4V | 86 RPM | 3.8 A | 铜 | ❌ 12.6V 超上限 |

**决定性理由：3S 满电 12.6 V，只有 C018 的电压范围（6~14 V）兼容。** C001 / C044 是 7.4 V 器件，接 3S 会被过压保护切断。

**而且 C018 在扭矩上也是三款里最强的**（额定扭矩 0.981 N·m vs C001 0.490 / C044 0.510）。

**三款尺寸重量完全相同（45.2×24.7×35 mm，55 g），所以换型号不影响机械设计。**

### 3.3 扭矩校核（按 3S 实际电压）

**3S 电压范围 9.0 V（空电）~ 12.6 V（满电），扭矩与电压近似线性：**

| 电压 | 堵转扭矩 | **额定扭矩** | 膝关节余量（需求 0.620 N·m） |
|---|---|---|---|
| 12.6 V（满电） | 31.5 kg·cm = 3.09 N·m | 1.030 N·m | 40% |
| **11.1 V（标称）** | **27.8 kg·cm = 2.72 N·m** | **0.907 N·m** | **32%** ✅ |
| 9.0 V（空电） | 22.5 kg·cm = 2.21 N·m | 0.736 N·m | 16% ⚠️ |

**各关节扭矩需求（机体 1.775 kg，D=2.5）：**

| 关节 | 需求扭矩 | 占 11.1V 额定 | 判定 |
|---|---|---|---|
| **膝**（唯一关键关节） | **0.620 N·m** | **68%** | ✅ 余量 32% |
| 髋俯仰（足偏 30 mm） | 0.326 N·m | 36% | ✅ 充裕 |
| **髋外摆**（臂 15 mm，摆 25°） | **0.019 N·m** | **2%** | ✅ 可忽略 |

**膝扭矩公式（已验证）：**
```
τ_knee = D · (m·g/4) · b        b = 膝力臂 = 28.5 mm（站立姿态）
       = 2.5 · (1.775·9.81/4) · 0.0285 = 0.620 N·m
```

⚠️ **低压报警建议设在 9.9 V（3.3 V/cell）**，不要用到接近空电（9 V 时余量只剩 16%）。

## 4. 电源与配电

### 4.1 电源架构

```
3S 21700 (11.1V 标称 / 9.0~12.6V)
  │
  ├─→ [TVS SMBJ15A] ─→ [P-MOS 反接保护] ─→ 电源开关
  │
  ├─→ 舵机动力（粗线直供，见 4.3）
  │      C018 × 12，3S 全程在 6~14 V 范围内 ✅
  │
  ├─→ 驱动板供电（细线，20~50 mA）
  │      Bus Servo Adapter (A)，9~12.6 V 输入 ✅
  │
  └─→ 5V/5A 降压模块（带散热片）
         └─→ USB-C 母座（CC 各 5.1kΩ 下拉）──→ Pi 5 的 USB-C 口
         └─→ 独立 3.3V 降压（≥800mA）──→ STM32 + JY901P + ESP32-C3
```

### 4.2 电流预算

| 负载 | 电流 |
|---|---|
| 12 舵机最坏（2 A 保护上限 × 12） | 24.0 A |
| 12 舵机额定常态 | 10.8 A |
| 12 舵机空载 | 2.4 A |
| Pi 5 峰值（25 W @12V，降压 85%） | 2.5 A |
| **母线最坏总电流** | **≈ 26.5 A** |

**但舵机自身的 2 A 过流保护会先动作，所以电芯和线材按 24 A 设计即可。**

### 4.3 配电方案（解决驱动板 5 A 限制）

⚠️ **Waveshare 官方 FAQ 明确：Bus Servo Adapter (A) 最大电流 5 A。** 而且它**没有板载稳压**（输入多少输出多少），所以它只是通路，不是配电盘。

**解决办法：电源旁路。** 从驱动板电源端子引粗线，直接连到舵机接口。

```
电池 + ──┬── 细线 ──→ 驱动板 DC/端子（仅供板子自身 20~50mA）
         └── 粗线 ──→ 舵机 V（各舵机）
电池 − ──┬── 细线 ──→ 驱动板 GND
         └── 粗线 ──→ 舵机 G   ← 必须与 V 成对旁路！
驱动板 D ──→ 舵机 1 D ──→ 舵机 2 D ──→ ...（12 个菊花链）
```

**三个前提：**
1. **V 和 G 必须成对旁路** — 只旁路 V 不旁路 G，大电流会从驱动板 G 回流，照样过流
2. **驱动板自己的 V/G 仍要接**（供板上串口 IC），但与舵机动力线分开走
3. **线径按最坏电流选，不是按常态 0.4 A**

| 每根线带的舵机数 | 最坏电流 | 线径 |
|---|---|---|
| 3 个 | 6.0 A | 18 AWG |
| 4 个 | 8.0 A | 18 AWG |
| **6 个** | **12.0 A** | **16 AWG** |
| 12 个 | 24.0 A | 14 AWG |
| 电池 → PCB 主回路 | 26.5 A | **16 AWG + XT30** |

### 4.4 电容配置（尽量直插，尽量少焊）

**舵机内部已有电解电容**，所以最有效的一级已具备。按"需要程度"分三档：

| 位置 | 器件 | 封装 | 处理方式 |
|---|---|---|---|
| **舵机母线**（最关键） | 电解 **2200 µF / 25 V** | **直插** | ✅ **必须**，但**装在接线端子上，不碰 PCB**（见下） |
| ESP32 的 5 V 输入 | 电解 100 µF + 瓷片 100 nF | **直插** | 🟡 **建议焊上**（WiFi 500 mA 尖峰） |
| Mini560 输入/输出 | 电解 470~1000 µF / 25 V | 直插 | 🟡 留焊盘 |
| STM32 的 5 V | 贴片 100 nF + 10 µF | 贴片 | 🟡 留焊盘（核心板自身有，双保险） |
| JY901P 的 VCC | 贴片 10 µF + 100 nF | 贴片 | 🟢 可不做（模块自带） |

#### ⭐ 舵机母线电容：装在端子上，PCB 上零电容

```
电池 + ──┬─── [粗线 14AWG] ─── 舵机 V
         │
     ┌───┴───┐  ← 螺钉式接线端子（可插拔）
     │   ○   │
     │   ○   │ ← 电容两脚直接插进端子拧紧
     └───────┘
         │
      [ 直插电解 2200µF/25V ]
         │
     ┌───┴───┐
     │   ○   │
     └───┬───┘
电池 − ──┴─── [粗线 14AWG] ─── 舵机 G
```

**好处**：零 PCB 焊接、可随时更换、位置正好在舵机供电点（效果最好）、想加大容量就并联插一个。

#### 为什么母线电容不能省

```
12 舵机同时启动 → 24 A 电流阶跃
电池到驱动板的线 → 寄生电感约 1 µH
压降 = L·di/dt → 无电容吸收会直接打在舵机供电上
```

#### 选型要点

- **耐压必须 25 V**（3S 满电 12.6 V，16 V 太紧）
- 低 ESR 即可（红宝石 ZLH / 丰宾 FR 等国产品牌），**不需要音响补品电容**
- **不要用一个大电容**：多个小电容并联的效果远好于 1 个大电容（降低 ESR/ESL，分散纹波电流）
- 如果做在 PCB 上：焊盘骑在铺铜上，**负极旁放 2~4 个过孔**到底层 GND；铜箔要"**先过电容、再进负载**"

#### 不同容值管不同时间尺度（不是重复）

| 容值 | 响应尺度 | 作用 |
|---|---|---|
| 2200 µF 电解 | ms 级 | 撑住 24 A 阶跃的持续时间 |
| 100 µF 电解 | µs 级 | 中期补充 |
| 10 µF 陶瓷 | 高频 | µs 级尖峰 |
| 100 nF 陶瓷 | 极高频 | ns 级开关噪声 |

### 4.5 电池电压检测（STM32 内部分压）

**方案：PA0 + 两个电阻 + 一个电容，全部直插。**

```
电池 + ──[ R1 = 100 kΩ ]──┬────────────→ PA0 (ADC1_IN0)
                          │
                     [ C1 = 100 nF ]   ← 与 R2 并联
                          │
                         GND
                          │
                    [ R2 = 22 kΩ ]
                          │
                         GND
```

| 项 | 数值 |
|---|---|
| 分压比 | `22 / (100+22) = 0.1803` |
| **12.6 V（满电）→ PA0** | **2.27 V** ✅ 余量充足（换 4S 也不用改） |
| 11.1 V → PA0 | 2.00 V |
| 9.0 V（空电）→ PA0 | 1.62 V |
| 静态耗流 | `12.6 / 120k = 105 µA` |
| 分辨率 | 0.806 mV/LSB ÷ 0.1803 = **4.5 mV** |
| 有效精度（含噪声） | **≈ 18 mV** ✅ 远超需求 |

#### 元件表（全部直插，总成本 ≈ ¥0.15）

| 元件 | 规格 | 封装 |
|---|---|---|
| R1 | **100 kΩ，1/4W，1% 金属膜** | 直插轴向 |
| R2 | **22 kΩ，1/4W，1% 金属膜** | 直插轴向 |
| C1 | **100 nF 直插瓷片**（标号 104） | 直插圆片 |

⚠️ **电阻必须买 1% 的金属膜**，不要买 5% 的碳膜。价格一样，但 5% 会让 12.6 V 读成 12.0 或 13.2 V。

#### C1 的作用（两个都不能省）

1. **解决源阻抗问题**：ADC 采样时从 C1 取电荷，不从 18 kΩ 电阻取，所以不受 STM32"源阻抗 < 1.2 kΩ"的限制
2. **低通滤波**：`f_c = 1/(2π·18k·100n) ≈ 88 Hz`，正好滤掉舵机 PWM 开关噪声，而电池电压变化是 Hz 级

**如果实在不想加 C1**：电阻要改成 **R1 = 4.7 kΩ / R2 = 1 kΩ**（源阻抗 825 Ω，合格），但静态耗流涨到 2.2 mA，且**抗噪差很多**——24 A 舵机电流下读数会明显跳动。**不推荐。**

#### 电池电压表（已有）

外接电压显示模块（直显式、不可通信）保留，用途：**充电时看电压、调试时人工确认**。它和内部检测不冲突，各司其职。

#### 3S 低压报警器（¥5，强烈建议）

```
3S 平衡头低压报警器 → 直接插在电池的 3 芯平衡头上
  · 8 个 LED 显示每一节电压
  · 任意一节 < 3.3 V 就蜂鸣
```

**为什么建议加**：STM32 检测的是**总电压**，看不出电芯不均衡。例如 `3.0 V + 3.5 V + 3.5 V = 10.0 V`，总压看着正常，但那一节 3.0 V 已接近损伤线。报警器按单体监测，正好补上这个盲区。

**零工作量**：不占引脚、不写固件、不碰 PCB、不破坏单点接地。

### 4.6 ⚠️ 接地（比电容重要得多）

**24 A 伺服电流流过逻辑地会产生 240 mV 地弹跳（按 10 mΩ 计），这会污染 IMU 读数并导致 1 Mbps 总线偶发通信错误。**

**四条铁律：**
1. **电池负极是唯一星点** — 舵机回流、降压模块回流都在这里汇合，不要互相串接
2. **伺服功率地 ≠ 逻辑地** — 让伺服电流的回流路径绕开逻辑区
3. **GND 铺铜分区**，中间留细连接带或 0 Ω 电阻单点连接
4. **1 Mbps 信号线远离功率铺铜**，间距 ≥3 mm，不要平行长距离走线

### 4.7 Pi 5 供电（⚠️ 不要直接接 GPIO 5V）

| 项 | 值 |
|---|---|
| Pi 5 官方推荐 | **5 V / 5 A（27 W）** |
| Pi 5 空闲 | ~3 W |
| Pi 5 推理负载 | 10~18 W（5 V 侧 2~3.5 A） |
| 模块发热（12.6→5 V，20 W 输出 @85%） | **3.5 W，需要散热片** |

**正确做法：**
```
3S → 5V/5A 降压 → PCB 上的 USB-C 母座（CC 各 5.1kΩ 下拉）→ C-to-C 线 → Pi 5 USB-C 口
```

| # | 要求 |
|---|---|
| 1 | 降压模块 **≥5 A**（航模 UBEC 或 MP1584/TPS54560 级） |
| 2 | **必须用 C-to-C 线**（A-to-C 线大概率不上电） |
| 3 | USB-C 座要接 **CC 下拉 5.1 kΩ × 2**，否则 Pi 5 可能不认 |
| 4 | 3S 最低 9.0 V → 5 V 压差 4 V，**任何 buck 都够，无 dropout 问题** |

⚠️ 若只给 5 V/3 A，Pi 5 能跑但会有欠压警告、限制 USB 供电预算。本项目不从 Pi USB 带大负载，**3 A 实际够用，但建议直接买 5 A 模块**。

**上电后实测：`vcgencmd get_throttled`，看是否出现 `0x50000`（欠压标志）。**

### 4.8 其它保护电路（建议做，但可留焊盘不焊）

| 电路 | 器件 | 为什么建议 |
|---|---|---|
| **TVS 钳位** | SMBJ15A（单向，钳 15~16 V） | 舵机堵转断开瞬间的电机反电动势尖峰可能到 20 V+，会击穿舵机内部 16 V 电容 |

## 5. 通信架构

### 5.1 总线舵机驱动板：Waveshare Bus Servo Adapter (A)（SKU 25514）

| 参数 | 值 |
|---|---|
| 输入电压 | 9 ~ 12.6 V（也支持 5~8.4 V，需与舵机匹配） |
| 通信接口 | UART |
| 波特率 | 与舵机一致（出厂 1000000） |
| **最大电流** | **5 A** ⚠️ |
| 板载稳压 | **无**（输入多少输出多少） |
| 驱动芯片 | **无**，板上是串口转换 IC（USB 侧是 **CH343**） |
| 尺寸 | 42 × 33 mm |
| 供电接口 | DC 5.5×2.1 mm + 绿色接线端子 |
| 舵机接口 | 2 个（**共享同一条 D 信号线**），标注 D / V / G |
| 跳线帽 | **A = UART 外部控制**；B = USB 控制 |

⚠️ **接线必须 RX-RX、TX-TX（不是交叉），跳线帽必须在 A 位置。**

⚠️ **只买 1 块驱动板即可** — 两个舵机接口共享同一条信号线，12 个舵机挂同一条总线。

### 5.2 串口分配（F103C8 的 3 个 USART 刚好用尽）

| 接口 | 连接 | 波特率 | 说明 |
|---|---|---|---|
| **USART1** | 树莓派 | 1 Mbps | 200 Hz 下 obs 240 B + act 24 B 仅需 53 kbps，余量巨大 |
| **USART2** | Bus Servo Adapter (A) | **1 Mbps** | 与舵机一致，不可改 |
| **USART3** | ESP32-C3 无线模块 | 115200~921600 | 低频调试用 |
| **I2C1（软件）** | JY901P | ~89 kHz 等效 | 约 7% CPU @200 Hz |
| SPI1 / SPI2 | 空闲 | — | 留给以后扩展 |

### 5.3 ⚠️ 为什么选 100 Hz 控制环（不是 200 Hz 或 1 kHz）

**关键约束：1 块驱动板 = 1 条 1 Mbps 总线 = 12 个舵机全在这一条线上。**

**读取是逐个舵机串行进行的**（发命令 → 舵机转向 → 回包 → 下一个），**瓶颈是串行转向延迟，不是带宽利用率。**

**实测/推算的时间账（1 Mbps，含舵机转向延迟 20 µs）：**

| 操作 | 字节数 | 耗时 |
|---|---|---|
| SyncWrite 下发 12 舵机 | 103 B | **1.02 ms** |
| syncRead 回读 12 舵机（位置+速度，4 B/舵机） | 136 B | **1.53 ms** |
| **合计** | | **2.55 ms / 10 ms = 26%** |
| 剩余给 IMU / 树莓派 / 无线 | | **7.45 ms（74%）** |

**替代方案：库自带的 `FeedBack(ID)` 逐舵机读（15 字节全字段）≈ 3.72 ms，总占用 47%，也装得下 100 Hz。** 建议先用它起步。

**❌ 已否决：200 Hz / 1 kHz 控制环。** 12 舵机挂单总线时，读一轮的串行时间就吃掉大半周期；1 kHz 物理上不可能（需要 2 块驱动板，但那样 USART3 就没法给无线了）。

**RL 策略在 50~100 Hz 完全够用**，而且舵机内部有 PID 内环，扰动抑制不依赖外环带宽。

### 5.4 总线物理层

| 项 | 结论 | 依据 |
|---|---|---|
| 舵机输出类型 | **开漏** | 已与卖家确认 |
| 上拉电阻 | **驱动板已有内置上拉** → PCB 上不需要 | 已确认 |
| 备选焊盘 | ⚠️ **建议留一个 1 kΩ 焊盘** | 万一内置上拉偏大、1 Mbps 下边沿不够快，可并联降阻 |
| TX 串阻 | 建议 100~220 Ω | 防"发送时舵机同时驱动"的短瞬间 |
| STM32 半双工 | 库用**普通全双工 UART**（TX/RX 分立），靠驱动板把两线并在总线 D 上 | 见库 `uart.c` |
| 依据 | Waveshare 官方参考原理图 | files.waveshare.com/upload/d/d3/Bus_servo_control_circuit.pdf |

**⚠️ 已知的物理层风险（待实测）**：开漏 + 1 Mbps + 12 舵机这个组合，上升沿时间 `t_r = 2.2·R·C` 可能不够快（`C_bus` 估计 340~630 pF）。**驱动板内置上拉的实际阻值决定了这件事。** 验证方法见 §8。

### 6.1 官方 F103 库评估（`doc/STServoBCL_keil_f103`）

**结论：✅ 用。协议层完全现成。**

#### 可直接原样搬用的文件

| 文件 | 内容 |
|---|---|
| `SCSLib/INST.h` | 指令码定义（PING/READ/WRITE/REG_WRITE/REG_ACTION/SYNC_READ/SYNC_WRITE） |
| `SCSLib/SC.c` / `SC.h` | 协议层：`genWrite` / `regWrite` / `regAction` / `syncWrite` / `Read` / `Ping`，含校验和、帧头检测、同步读 |
| `SCSLib/ST.c` / `ST.h` | 应用层：**`SyncWritePosEx`**（批量下发）/ `WritePosEx` / `WheelMode` / `EnableTorque` / **`FeedBack`**（一次读回 15 字节全字段）/ `ReadPos`/`ReadSpeed`/`ReadLoad`/`ReadVoltage`/`ReadTemper`/`ReadMove`/`ReadCurrent` / `getErr` |
| `SCSLib/SCServo.h` | 汇总头 |
| `examples/wiring.c` / `wiring.h` | `SysTick` + `millis()` + `delay()` |

**`SyncWritePosEx` + `FeedBack` 正好就是"批量下发 + 批量回读"这两件事。** 这省掉的工作量按周计。

#### 必须替换的文件

| 文件 | 原因 | 替换工作量 |
|---|---|---|
| `SCSLib/uart.c` | 用 **StdPeriph 库**，与 Cat 项目的 **HAL** 冲突 | **40~60 行**（只需实现 4 个函数） |

**库需要你提供的接口只有 4 个：**
```c
void    Uart_Init(uint32_t baudRate);
void    Uart_Send(uint8_t *buf, uint8_t len);
int16_t Uart_Read(void);      // 返回 -1 表示无数据
void    Uart_Flush(void);
```

`SCSerail.c` 里的 `writeSC` / `readSC` / `rFlushSC` / `wFlushSC` 都是纯软件逻辑，**不依赖任何外设库。**

### 6.2 ⚠️ 必须修改的 5 处（否则会出问题）

| # | 问题 | 位置 | 修改 |
|---|---|---|---|
| **1** | **StdPeriph / HAL 冲突** | `uart.c` | 用 HAL 或寄存器重写那 4 个函数 |
| **2** | **接收缓冲可能溢出** | `uart.c` `uartBuf[128]` | 环形缓冲扩到 **512 B**。syncRead 读完整 15 字节需要 `12×(6+15)=252 B`，超 128 B。只读位置+速度需 120 B（压线通过） |
| **3** | **环形缓冲无溢出检测** | `uart.c` `USART1_IRQHandler` | 加溢出计数 |
| **4** | **`syncReadBegin` 用了 `malloc`** | `SC.c:337` | 换成静态缓冲。STM32 上控制循环用动态内存有堆碎片化风险，且失败返回 NULL 无人检查 |
| **5** | **`IOTimeOut` 是"每字节超时"不是"整帧超时"** | `SCSerail.c:11` `IOTimeOut = 5000` | `readSC` 每收到一字节就 `t_user=0`，所以是每字节超时。**舵机不存在时一帧阻塞 ~0.5~1 ms；12 个全失联累计 6~12 ms，直接吃掉整个 10 ms 周期。必须在外层加整帧超时** |

**另外两个要注意：**
- **`SyncWritePosEx` 返回 `void`**（无错误码）→ **必须用 `getErr()` 监视通信状态**
- `SCDelay()` 里有总线切换延时（约 10 µs）→ 说明库是认"半双工需要转向延时"的

### 6.3 控制环设计（100 Hz）

```
【每周期 10 ms】
  ① syncRead 回读 12 舵机（位置+速度，4 B/舵机）   1.53 ms
     起步方案：FeedBack(ID) 逐舵机读，15 B/舵机     3.72 ms
  ② 读 JY901P（软件 I2C）                          ~0.20 ms
  ③ 组 obs → 发树莓派                              ~0.05 ms
  ④ 收 action                                     ~0.03 ms
  ⑤ SyncWritePosEx 下发 12 舵机                    1.02 ms
  ⑥ 安全层：整帧超时 / 限幅 / 心跳 / 无线遥测
  ─────────────────────────────────────────────
  总线占用 26%，CPU 预估 30~40%
```

### 6.7 电池电压监测（ADC + 低压保护）

**电路见 `§4.5`。这里只讲固件侧。**

#### ADC 配置

```
ADC1，通道 0（PA0）
  · 12 bit，右对齐
  · 采样时间：239.5 周期（最长，配合 18 kΩ 源阻抗 + C1 更稳）
  · 定时器触发 + DMA，采集频率 10 Hz
  · 每通道 16 次滑动平均 → 等效精度约 2 个码
```

#### 换算

```c
// ⚠️ ADC_VREF 必须按实测值填，不能写死 3.3f（AMS1117 精度 ±2~3%）
#define ADC_VREF    3.28f                        // ← 校准值（见下）
#define BATT_DIV    (22.0f/(100.0f+22.0f))       // 0.18033
#define BATT_GAIN   (ADC_VREF / 4095.0f / BATT_DIV)

vbat = adc_avg[0] * BATT_GAIN;                   // 伏特
```

#### ⚠️ 必做：两步校准（一次性，5 分钟）

Blue Pill 的 **VDDA 直接连 VDD**，没有独立基准，所以 ADC 的"3.3 V"其实是"当前的 3.3 V"。

```
第 1 步：万用表量 STM32 模块的 3.3V 引脚 → 填入 ADC_VREF
第 2 步：机器人静止，万用表量电池电压，与固件读数对比
        → 差值用于微调 BATT_DIV
```

**两步做完精度可达 ±50 mV，对电池监测完全够用。**

#### 低压保护阈值（按 `§3.3` 的扭矩余量推导）

| 电压 | 每节 | 膝扭矩余量 | 动作 |
|---|---|---|---|
| > 10.5 V | > 3.50 V | > 25% | ✅ 正常 |
| **10.5 V** | 3.50 V | 25% | ⚠️ **警告**（LED 闪 / 无线推一条告警 / 上报树莓派） |
| **9.9 V** | 3.30 V | 16% | 🔴 **建议停机**（主动上报树莓派） |
| **9.3 V** | 3.10 V | < 10% | 🚨 **强制保护：全部舵机 Torque Disable（失力趴下）** |

**为什么最低阈值要"失力趴下"而不是"保持站姿"：**

> 电池快空时若让舵机继续保持站姿，电流会持续拉高 → 电压进一步塌陷 → 舵机可能进入欠压保护或直接掉电。
> **主动失力趴下比硬撑到掉电安全得多**，而且趴下后电流立刻降下来。

#### 实现注意

| # | 注意点 |
|---|---|
| 1 | **`EnableTorque(ID, 0)` 对每个舵机是一次单独通信**（12 个 ≈ 3.3 ms）。只在上电和停机时做，**不要放进 100 Hz 控制环** |
| 2 | **不要"检测到就立刻切"** —— 电池在舵机启动瞬间会跌几百 mV。**要连续 N 次采样（如 20 次 = 2 秒）都低于阈值才触发**，否则误判 |
| 3 | ADC 走线要**远离舵机功率区**（模拟信号，24 A 开关噪声会耦合） |
| 4 | 分压电阻要**靠近电池接入点**，避免走长线后再分压 |

#### 兜底：3S 低压报警器（¥5）

见 `§4.5`。**报警器按单体监测，补上"总压看不出电芯不均衡"的盲区**，且完全不占固件资源。

#### 电流检测：已放弃

**不做。** 丢失的能力（记录备用）：
- 电量精确估算、续航预测
- 硬件级堵转检测（现在依赖舵机自带的 2 A 过流保护 + 固件 `getErr()`）
- 碰撞检测（少了 `Present Current` 这个观测）
- 电池内阻趋势

**替代**：固件可轮询 `FeedBack(ID)` 读 `PRESENT_LOAD`（地址 60/61）做软件级堵转兜底，低频（20 Hz）读 4 个膝关节即可。

## 7. 无线模块（ESP32-C3）

**用途：低频调试，接 STM32 的 USART3。**

| 项 | 内容 |
|---|---|
| 型号 | **ESP32-C3 开发板** |
| 接口 | UART（3.3 V 电平，与 STM32 直接匹配，**不需要电平转换**） |
| 固件 | ESP-AT 固件，或自写 UART↔WiFi 透传（几十行） |
| 使用方式 | ESP32 开 WiFi 热点，笔记本连上后用 TCP/UDP 工具收发，**PC 侧零驱动** |
| 波特率 | 115200 ~ 921600 |
| **供电** | ⚠️ **必须独立 3.3 V（≥800 mA）** — WiFi 发射峰值 500 mA，挂在 STM32 核心板 LDO 上会拉垮 3.3 V 导致 STM32 复位 |

**带宽需求（USART1 对树莓派，200 Hz 下 obs 240 B + act 24 B）：**
| 频率 | 需要波特率 |
|---|---|
| 100 Hz | 26.4 kbps |
| **200 Hz** | **52.8 kbps** → 115200 已够 |

**无线只做低频监控 + 遥控。完整遥测日志应走有线（Pi↔PC）。**

### 7.1 ❌ 已否决的无线方案

| 方案 | 否决理由 |
|---|---|
| ESP32 跑 BLE NUS | 延迟 10~50 ms，看日志够用但遥控会很难受 |
| Zigbee | PC 侧需要协调器，多一层工程量 |
| 经典蓝牙串口（HC-05 类） | 115200 上限，老，Android 9+ 兼容差 |
| LoRa | 速率 kbps 级，差三个数量级 |
| 2.4G 透传模块（nRF24L01+PA 等） | 延迟最低（<5 ms），但 PC 侧要再插一个模块；**保留为备选** |

## 9. 决策记录（为什么这么定）

| 决策 | 结论 | 关键理由 |
|---|---|---|
| 自由度 | 3 DOF/腿（外摆+髋俯仰+膝） | 2 DOF 失去侧向平衡能力，转向和抗侧推全靠策略硬扛 |
| 腿型 | **串联直驱** | 仿真里 1:1 对应，故障可诊断，标定工作量最小。四连杆的转动惯量优势在 1~2 Hz 步频下不到 5% |
| 舵机 | **ST-3215-C018** | **3S 电压范围只有它兼容**（6~14 V），且额定扭矩是三款里最强的 |
| 电源 | **3S 21700** | 用户已有电池盒；Pi 5 供电从"升压"变"降压"，更简单 |
| 控制环 | **100 Hz** | 单总线带 12 舵机时，读一轮的串行时间决定上限；RL 50~100 Hz 已够 |
| STM32 | **保留 F103C8** | 复用 Cat 项目那块板 + 已有固件分层 |
| 驱动板 | **1 块 + 电源旁路** | 5 A 限制靠外接粗线绕开；1 块板带 12 舵机（两个接口共线） |
| ROS 2 | **不用** | DDS 抖动大，不能进控制环；等接 LiDAR 时再引入 |
| IMU 接口 | **软件 I2C** | **F103 硬件 I2C 有真实勘误**（BUSY 卡死、总线锁死难恢复）；软件 I2C 在此场景 CPU 开销相近且风险为零 |
| IMU 选型 | **JY901P（已有）** | 模块内部做融合，MCU 零算力开销；前提是波特率调到 921600 |
| 无线 | **ESP32-C3** | 灵活（以后可扩展手机遥控/网页调参），UART 3.3 V 直连 |
| 电容 | **母线 2200 µF 为主，装在接线端子上** | 舵机内部已有电解电容；**母线电容装在螺钉端子上，PCB 上零电容**；其余留焊盘 |
| 元件封装 | **尽量直插** | 可焊贴片但优先直插。实际必须直插的只有：母线 2200 µF、ESP32 的 100 µF + 100 nF、分压的 2 电阻 + 1 瓷片 |
| **电池电压检测** | **STM32 内部 ADC + 分压**（100 kΩ / 22 kΩ + 100 nF，全直插） | 让低压保护自动化，不依赖人工看显示模块。成本 ¥0.15。**需两步校准**（`§6.7`） |
| **电流检测** | **❌ 不做** | 省掉 INA181 + 采样电阻。堵转保护降级为依赖舵机自带 2 A 过流保护 + 固件 `getErr()` 兜底 |
| **电压显示模块** | 保留（外接、直显，不通信） | 用途：充电时看电压、调试时人工确认 |
| **3S 低压报警器** | **建议加（¥5，插平衡头）** | 补上"总压看不出电芯不均衡"的盲区；零工作量、不碰 PCB |
| **足底传感器** | **v1 不加**（结构预留） | 用舵机 `Present Load` 字段代替。走线要跨 3 个关节，是小型四足最常见故障源；Load 是舵机内部量，无额外故障点 |
| Pi 5 供电 | **USB-C 母座 + C-to-C 线** | 不直接接 GPIO 5V（绕过 PD 协商和保护电路） |

## 附录 A：关键物理公式（已在本轮讨论中验证）

```
【膝扭矩】（站立姿态，大腿 = 小腿 = L/2）
  b = 膝力臂 = 髋俯仰轴到足端的垂直投影的一半 × 2      ← 由站姿 h/L 决定
  τ_knee = D · (m·g/4) · b
  其中 D = 动态系数（四腿静态 1.0，单腿支撑 2.0，落地下压 2.5，奔跑 3.5）
  站立 h/L = 0.88 时：b = 28.5 mm（L=120mm）

【髋俯仰扭矩】
  τ_hip ≈ D · (m·g/4) · b_hip      b_hip = 足相对髋的水平偏移

【髋外摆扭矩】（极小，通常可忽略）
  τ_abd = m_leg · g · L_coxa · sin(θ_abd_max)

【舵机工作点电流】（扭矩与电流近似线性）
  I = τ / Kt        Kt = 11 kg·cm/A = 0.1079 N·m/A（C018）

【开漏总线上升时间】
  t_r(10-90%) = 2.2 · R_pullup · C_bus
  1 Mbps 要求 t_r ≤ 0.3 bit = 300 ns

【总线带宽占用】
  利用率 = (下行字节 + 上行字节) × 10 bit/字节 × 频率 / 波特率
```
